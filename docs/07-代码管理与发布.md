# 07 代码管理与发布

> 依据：[00-提示词](00-提示词.md) 第 10、11 节；[01 总体方案](01-总体方案.md) 3.1 节 T8。本文回答「代码放哪、怎么提交、怎么自动构建和测试、密钥怎么管、怎么发版上架」。

## 1. 仓库

- 仍是现在的 GitHub 私有仓库 `lwopgkne-byte/pour`；iOS（`ios/`）、AI 网关（`gateway/`）、网页版（`shared/ server/ web/`）、Skill、评测、标准答案都在里面
- 产品主人在 Mac 上：`git clone` → `ios/scripts/bootstrap.sh` → 打开 Claude Code，就有完整代码和全部方案
- 工程文件由 XcodeGen 从 `ios/project.yml` 生成，**不提交生成出来的 `.xcodeproj`**（自动构建时先生成）

**永远不进仓库**（`.gitignore` 加上，提交前自动检查）
- 密钥和证书：`.env`、`*.p8`、`*.p12`、`*.mobileprovision`、`Secrets.xcconfig`
- 个人数据：`data/`、`notes/`、`backups/`
- 构建产物：`DerivedData/`、`build/`、`xcuserdata/`、生成的工程
- 评测结果里的个人内容（评测只用用例数据，不碰真实数据）

## 2. 分支和标签

> **主分支保护**：私有仓库要 GitHub Pro 才能开，**2026-10-17 产品主人决定不开**（用免费版）。规矩不变、靠流程守：功能分支 → 本机推送前检查 → 合并请求（GitHub Actions 跑 iOS 检查）→ 产品主人验收后才合并，不直接往 `main` 推。

| 名字 | 用途 | 规矩 |
|---|---|---|
| `main` | 永远能构建、能跑、测试全过 | 只通过合并进来；**GitHub 上开主分支保护**（M0）：CI 没过不能合并、不能强推 |
| `feature/ios-mX-名字` | 一个模块一个分支 | 自验收、产品主人验收都过了才合并 |
| `feature/gateway-名字` | 网关的改动 | 评测过了才合并 |
| `release/ios-1.0` | 发版前的稳定分支 | 只修问题，不加功能 |
| `hotfix/…` | 线上紧急修复 | 修完同时合回 `main` |

| 标签 | 例子 | 什么时候打 |
|---|---|---|
| 模块验收 | `ios-m1-accepted` | 产品主人验收通过、合并后 |
| App 版本 | `ios-v1.0.0` | 提交 App Store 的那个版本 |
| 网关版本 | `gateway-v1.0.0` | 每次部署到正式环境 |
| 网页版 | `v1.17.x` | 照旧（冻结后只修问题） |

## 3. 提交和推送

- 提交说明用中文，说清改了什么、为什么；结尾带协作者署名行
- 一次提交只做一件事；提交前本地检查全过（Git 钩子自动跑，**不许用 `--no-verify` 跳过**）
- 产品主人说「今天先到这」：跑测试 → 提交 → 推送（没做完也推到功能分支）
- 开始工作先 `git pull`

## 4. 自动构建和测试（CI）

> **现阶段（2026-10-17）**：没有加入苹果开发者计划，Xcode Cloud 用不了。iOS 的检查是 `ios/scripts/check.sh`：推送前钩子在改了 `ios/` 时自动跑，合并请求进 `main` 时 GitHub Actions（`.github/workflows/ios.yml`，macOS 机器）再跑一遍。下表是加入后的样子。

| 流水线 | 在哪 | 触发 | 做什么 |
|---|---|---|---|
| iOS 提交检查 | Xcode Cloud | 推送到功能分支、合并请求 | 生成工程 → 编译 → SwiftLint → 单元 + 对拍 + 数据 → 截图 |
| iOS 主干 | Xcode Cloud | 合并到 `main` | 上面全部 + 核心界面流程 + 演示数据检查 → **自动发到 TestFlight 内部测试** |
| iOS 每晚 | Xcode Cloud | 每天夜里 | 全部界面流程、无障碍、性能、弱网、同步、演示数据检查 40 个日期 |
| iOS 发版 | Xcode Cloud | `release/` 分支 | 归档 → TestFlight 外部测试 → 等人工确认后提交审核 |
| 网关 / TypeScript | GitHub Actions | 推送、合并请求 | 类型检查、单元测试、日志不含原话检查、标准答案是否需要重新导出 |
| AI 评测 | GitHub Actions | 改了 Skill / 流水线 / 模型；每周一次 | 全量评测，有花费上限；不达标就标红、不能合并 |

**Xcode Cloud 的额度**：开发者账号每月含 25 小时。估计每天夜里约 40 分钟、每次合并约 15 分钟，忙的时候会超；超了买 100 小时档（每月 49.99 美元），或者把每晚的一部分放到产品主人的 Mac 上跑。M0 实测后定。

## 5. 密钥和证书

| 东西 | 放哪 | 谁能碰 |
|---|---|---|
| 签名证书、描述文件 | Xcode Cloud 自动管理签名 | 自动构建 |
| App Store Connect 的接口密钥 | Xcode Cloud / GitHub Actions 的密钥设置 | 自动构建 |
| DeepSeek 等模型的密钥 | 云服务的密钥管理（网关运行时读取） | 网关 |
| App Attest 配置（设备证明） | 云服务的密钥管理 | 网关 |
| 本机开发用的配置 | `ios/Config/Secrets.xcconfig`（不提交） | 产品主人自己填 |

**沿用网页版的安全规矩**：开发过程中 Claude 不读取、不打印、不修改任何密钥文件；密钥不进仓库、不进 App 安装包（App 里只有网关的地址）。

## 6. 版本和兼容

- App 版本号按「大.小.修」：`1.0.0` 首发；构建号由 CI 自动递增
- 网关接口带版本：`/v1/...`；同时支持当前和之前两个 App 版本；只有安全问题才强制升级
- Skill 有自己的版本号（文件头里），改了就升，评测报告里记着用的是哪个版本
- **远程开关**（网关下发）：新功能可以先对一部分人打开；出问题一键关掉，不用等苹果审核

## 7. 发版流程和上架清单（上架时用；内测阶段只用 TestFlight 那几步）

**流程**
1. 从 `main` 拉 `release/ios-x.y`；跑发布前全部检查（测试方案第 6 节）
2. TestFlight 外部测试 3–7 天，看崩溃、卡顿、反馈
3. 提交审核（附审核说明，见演示方案 3.2）
4. 通过后**分阶段发布**（苹果的 7 天逐步放量）；有问题可以暂停
5. 发布后合回 `main`、打标签、写 CHANGELOG

**上架清单**（逐条打勾）
- [ ] 版本号、构建号、更新说明（中文大白话）
- [ ] 商店信息：名字、副标题、描述、关键词、截图（自动生成）、预览视频
- [ ] **ICP 备案号**已填，和工信部登记的信息一致
- [ ] **生成式 AI 公示**：所用模型名称和备案号（App 内 + 商店描述）
- [ ] 隐私：隐私政策链接、App 隐私标签（收集什么、用来做什么）、敏感个人信息的单独同意
- [ ] 用户协议、AI 生成内容标识说明
- [ ] 订阅：价格、试用、恢复购买、取消说明；付费页符合苹果和国内规定
- [ ] 「删除所有数据」入口（设置 → 隐私中心）；隐私清单 `PrivacyInfo.xcprivacy` 和真实行为一致
- [ ] 年龄分级；未成年人相关要求（登记时确认的）
- [ ] 加密出口合规声明（只用系统的 HTTPS）
- [ ] 审核说明和演示方式
- [ ] 发布前全部检查通过、全量评测通过
- [ ] 网关正式环境已部署对应版本、远程开关已设好
- [ ] 支持页面和联系方式

## 8. 网关的发布

- 两套实例轮流更新（一套在服务时更新另一套），出问题一分钟内切回
- 数据库改动只做「向后兼容」的（先加后删），不停机
- Skill 改动：评测通过 → 先对测试环境 → 再对一小部分正式用户（远程开关）→ 全量

## 9. 两台 Windows + 一台 Mac 怎么分工

| 电脑 | 做什么 |
|---|---|
| Mac | iOS 的全部开发、构建、真机调试；也能做网关 |
| 家里的 Windows | 网页版照常能跑（作为对拍的参照）；可以做网关和 TypeScript 部分 |
| 公司的 Windows | 只开发（网关、TypeScript），不跑真实数据 |

M0 时在 `CLAUDE.md` 里加一节「iOS 开发」，写清 Mac 上的命令和规矩（另一台电脑上的 Claude 没有这里的记忆，靠它）。

## 10. 备份和依赖

- 代码：GitHub + 标签；每个上架版本的符号文件（dSYM）由 Xcode Cloud 保存
- 网关数据库（只有设备编号和用量；以后有付费时加上购买凭证）：云服务每天自动备份
- 第三方库：Swift 包锁定版本（`Package.resolved` 提交）；npm 锁定版本；每周自动检查更新（Dependabot），升级要过全部测试；许可证清单放在 `docs/ios/许可证.md`
