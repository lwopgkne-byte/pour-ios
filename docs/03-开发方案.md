## 1. 技术选型（每条在 M0 写成一份架构决定记录 ADR）

| # | 方面 | 选择 | 为什么 | 没选的和原因 |
|---|---|---|---|---|
| A1 | 语言 | **Swift 6**（严格并发检查） | 苹果平台的一等公民；编译期发现数据竞争 | — |
| A2 | 界面 | **SwiftUI 为主**；输入栏等极少数地方用 UIKit 包一层 | 系统组件、Liquid Glass、动效都是 SwiftUI 优先；中文输入法的标记文字、输入框高度变化用 `UITextView` 控制更稳 | React Native / Flutter：拿不到最好的原生手感和系统新能力，「一线水准」做不到 |
| A3 | 最低系统 | **iOS 26**，用 iOS 27 SDK 构建 | 见总体方案 D3 | — |
| A4 | 架构 | **分层 + 单向数据流**：页面 ← `@Observable` 模型 ← 服务（协议）← 数据库 / 网关；依赖注入用 `swift-dependencies` | 轻、好测、Claude 好维护 | TCA（可组合架构）：很强但样板代码多，对这个规模不划算 |
| A5 | 数据库 | **SQLite + GRDB**；界面观察数据用 Point-Free 的 **SQLiteData**（建在 GRDB 上，带 CloudKit 同步） | 发现引擎、统计要写复杂查询，SQL 最直接、最快；网页版本来就是 SQLite，表结构能对上 | SwiftData：复杂查询和性能不可控，迁移不透明 |
| A6 | 同步 | **CloudKit 私有库**（经 SQLiteData 的同步引擎）；同步层做成可替换的协议 | 数据在用户自己的 iCloud，我们不碰；免费；中国区由云上贵州运营 | 自建同步：要存用户日记，隐私和合规风险大，以后做安卓时再加「端到端加密同步」 |
| A7 | 规则和计算 | **PourCore**：纯 Swift 包，不依赖界面和数据库，iOS 和 macOS 都能跑 | 网页版 `shared/src` 的移植；能在 Mac 命令行里对拍、跑评测 | 在手机里跑 JavaScript 复用 TS：两套语言、桥接开销、调试难 |
| A8 | AI 网关 | **TypeScript（Node 22 + Fastify）**，部署在国内云 | 沿用网页版的整理流水线、Skill、程序把关和评测，准确率原样继承；改提示词不用等苹果审核 | 用 Swift 重写流水线：要重新赚回 99.9%，风险大、没收益 |
| A9 | 账号 | **用 Apple 登录** + 网关签发的短期令牌；**App Attest** 证明请求来自真的 Pour | 防止有人盗用网关刷我们的 AI 费用 | 只用令牌：令牌可以被抓包盗用 |
| A10 | 付费 | **StoreKit 2**；网关用 App Store Server API 和服务器通知校验订阅 | 苹果官方、最新 | 第三方订阅平台：多一家拿用户数据 |
| A11 | 通知 | **本地通知为主**：提醒时间在手机上算好、本地排；后台刷新预先算好早上的回顾 | 不依赖服务器；省电、私密 | 服务器推送：要知道用户的作息和内容，不需要 |
| A12 | 语音 | **SpeechAnalyzer**（iOS 26，端侧，支持中文）；不达标时退回系统听写 | 原话不出手机就转成文字 | 云端语音识别：原话的录音要上传 |
| A13 | 按意思搜索 | **bge-small-zh 转成端侧模型**（Core ML / iOS 27 的 Core AI），向量存在本机数据库 | 网页版已经用它，中文效果验证过；端侧不花钱、不出手机 | 苹果自带的句向量：中文支持不确定 |
| A14 | 图表 | **Swift Charts**；时钟、星图、热力图、心情像素用 `Canvas` 自绘 | 原生、无障碍（音频图表）、动画好 | 网页图表库：不原生 |
| A15 | 工程生成 | **XcodeGen**（`project.yml` 生成工程文件） | 工程文件不再有合并冲突；Claude 改起来清楚 | 手改 `.pbxproj`：容易冲突、难审查 |
| A16 | 代码风格 | SwiftLint + swift-format；令牌检查是 SwiftLint 的自定义规则 | 自动守住设计系统 | — |
| A17 | 观测 | MetricKit + 系统日志标记（signpost）+ Xcode Organizer；网关用云监控 | 不引入第三方 SDK 拿用户数据 | 第三方崩溃收集：上线后视需要再评估（要在隐私政策里写） |
| A18 | 依赖政策 | 能用系统的不用第三方；每个第三方库写 ADR（许可证、维护情况、大小） | 少依赖、少风险 | — |
| A19 | 多语言 | 界面文字全部进 String Catalog，简体中文为基准；日期、数字、金额用系统格式化 | 海外第二阶段时只加翻译，不改代码 | 文字写死在代码里：以后要全部翻出来 |

## 2. 工程结构

和网页版同一个仓库（总体方案 D9）：

```
2.0/                         （仓库根目录）
├─ shared/ server/ web/      网页版：冻结为「参照版」，继续能跑、能测
├─ skills/                   AI 规则（网页版、网关共用，只有一份）
├─ evals/                    评测集和评测程序（网关、pour-cli 都用）
├─ fixtures/golden/          网页版算出的「标准答案」（JSON），Swift 对拍用
├─ gateway/                  新：商业版 AI 网关（TypeScript，引用 shared 和 server/src/ai）
├─ ios/
│  ├─ project.yml            XcodeGen 工程描述
│  ├─ App/                   App 入口、标签栏、导航、依赖装配
│  ├─ Packages/
│  │  ├─ PourCore/           规则和计算（纯 Swift，对拍网页版）
│  │  ├─ PourData/           数据库：表、迁移、读写、同步
│  │  ├─ PourAI/             网关客户端、问答循环和工具、端侧语音和向量
│  │  ├─ PourDesign/         设计系统：令牌、组件、图表、动效、触感
│  │  └─ Features/           今天、回顾、关于我、钱、目标、搜索、设置、倾倒……一个功能一个包
│  ├─ Gallery/               设计画廊 App（不上架）
│  ├─ Extensions/            小组件、分享扩展、App Intents、控制中心
│  ├─ Tools/pour-cli/        Mac 命令行：对拍、问答评测、演示数据检查、性能基准
│  ├─ Tests/                 界面测试、截图测试、性能测试
│  └─ scripts/               bootstrap.sh（新 Mac 一键装环境）等
└─ docs/ios/                 这些方案、能力对照表、模块小方案、验收报告
```

**依赖规则**（CI 检查，违反就不能合并）
- `PourCore` 什么都不依赖（只用 Foundation）
- `PourData` 只依赖 `PourCore`；`PourAI` 依赖 `PourCore`、`PourData`
- `PourDesign` 不依赖任何业务包
- 功能包之间**不互相依赖**，通过 App 层的导航和协议连起来
- 功能包不直接写 SQL，只调用 `PourData` 的读写接口

## 3. 数据设计

**沿用网页版的表**（notes 原话、entries 记录、entry_sources 来源、entry_versions 版本、categories 类别、dictionary 词典、goals 目标、findings 发现、theme_names 主题名、summaries 总结、messages 回顾和报告、settings 设置……），按手机和多设备的情况改这几处：

| 改动 | 网页版 | iOS | 为什么 |
|---|---|---|---|
| 主键 | 自增整数 | **UUID** | 两台设备各自新建，同步时不能撞号 |
| 时间 | 本地时刻（不带时区） | 本地时刻 **+ 时区标识** | 出差、旅行跨时区时「几点」不乱；日界线照旧按当地时间 |
| 删除 | 软删除（`deleted_at`） | 同 + 同步的「墓碑」 | 另一台设备也要知道删了 |
| 版本历史 | `entry_versions` | 同，**永远不在同步里丢** | 冲突时以它为准还原 |
| 冲突 | 不存在 | 同一条记录两台设备都改了：按修改时间取后者，旧的进版本历史，收据里说一句 | 不丢数据、可追溯 |
| 结构版本 | 19 个迁移累积 | iOS 从**一个干净的第 1 版**开始 | 网页版的历史包袱不带过来；搬家程序负责转换 |
| 向量 | `embeddings` 表 | 同（端侧计算） | 按意思搜索、主题归堆 |

**从网页版搬家**（M13）：网页版导出一个包 → iOS 导入：整数编号换成 UUID（保持引用关系）、补上时区、原话和版本历史原样保留；搬完逐表对数。

**加密和锁**：数据库文件用系统数据保护（锁屏后不可读）；可选 Face ID 锁 App；网关令牌放钥匙串。

## 4. 并发和性能做法

- 界面模型在主线程；数据库用 GRDB 的连接池（读并发、写串行）；**重计算（发现引擎、关于我、一年）放后台**，算完回主线程
- 计算结果按「数据版本」缓存：数据没变不重算；新记一段话只让受影响的页面失效
- 列表全部懒加载；图片和图表按需绘制；长时间轴分页
- 启动时只做三件事：打开数据库、显示今天、准备输入栏；其余（向量模型、同步、统计预热）延后到第一帧之后

## 5. 性能预算（自动测试 + 真机量，不达标不能验收）

基准机：**iPhone 13**（中等偏旧的机型）；数据：演示数据 9 周 + 合成的 3 年数据（约 1.1 万段话）。

| 指标 | 预算 |
|---|---|
| 冷启动到能输入 | ≤ 400 毫秒（苹果建议的首帧时间） |
| 热启动 | ≤ 150 毫秒 |
| 按发送 → 原话出现在时间轴 | ≤ 100 毫秒 |
| 按发送 → 收据出现 | 中位数 ≤ 3 秒，九成 ≤ 6 秒（受模型影响；期间有进度） |
| 滚动掉帧（hitch） | < 5 毫秒/秒（苹果的「良好」线）；高刷屏 120 帧 |
| 关于我主页计算 | ≤ 150 毫秒（9 周）；≤ 400 毫秒（3 年，后台，先显示缓存） |
| 发现引擎一次全量 | ≤ 300 毫秒（9 周） |
| 按意思搜索 | ≤ 100 毫秒（1 万段） |
| 问答首字 | 中位数 ≤ 1.5 秒 |
| 内存 | 常态 ≤ 150 MB |
| 安装包 | ≤ 60 MB（向量模型首次需要时再下载） |
| 后台耗电 | 每天后台任务合计 ≤ 30 秒 |

## 6. 模块计划

每个模块：**目标 → 范围 → 和网页版的对照 → 自验收标准（数字）→ 产品主人验收要点**。开工前写成模块小方案（`docs/ios/模块/Mx-名字.md`），确认后再做。

### M0 开工准备
- **目标**：整条流水线打通——仓库里的代码自动构建、自动测试、自动装到产品主人的手机上
- **范围**：Mac 环境一键脚本；XcodeGen 工程和分层的 Swift 包骨架；一个只有启动页的空 App；Xcode Cloud（推送 → 构建 → 测试 → TestFlight 内部测试）；GitHub Actions（网关和 TS 测试）；ADR 0001–0019；**能力对照表**（从 SPEC 和各 PRD 逐条整理）；标准答案导出脚本 `scripts/export-golden.ts`；合规启动清单；**Bundle ID 定稿**
- **自验收**：CI 全绿；在一台干净的 Mac 上按 README 15 分钟内装好环境；空 App 在真机上打开
- **产品主人验收**：收到 TestFlight 邀请，装上，看到 Pour 的启动页

### M1 设计系统
- **目标**：视觉方向在真机上定下来；所有组件准备好
- **范围**：令牌（颜色亮暗、字体三种声音、间距、圆角、动效三档、触感）；原子和分子组件的全部状态；图表基础（迷你图、日历像素、条形）；设计画廊 App；**真机样张 5 屏**（今天、收据、关于我、钱、回顾，用演示数据静态渲染）；App 图标三个方案；令牌检查和对比度测试
- **自验收**：设计审查清单全过；对比度测试全过；截图矩阵（亮暗 × 两种字号 × 两种宽度）全部看过
- **产品主人验收**：在手机上翻画廊和样张；选 App 图标；确认颜色、字体、动效 → **锁定令牌 v1**（之后改令牌要再确认）

### M2 数据和演示数据
- **目标**：手机上有和网页版一样的数据结构，和一个能翻的演示人生
- **范围**：数据库第 1 版（UUID、时区）；迁移框架；读写接口；**演示数据生成器移植到 Swift**（9 周那个人，埋 5 真 5 假）；新增「一整年」的演示数据（让「你的一年」能演示）；「看看示例」用的独立沙盒库
- **自验收**：9 周演示数据在 iPhone 13 上生成 ≤ 1 秒；和网页版对拍：每张表的行数、每天的原话和记录一致；迁移测试
- **产品主人验收**：开发菜单里切到演示数据，在简单列表里翻原话和记录

### M3 规则和计算（PourCore）
- **目标**：网页版 `shared/src` 的全部规则移植到 Swift，算出来一模一样
- **范围**：按依赖顺序移植——日期时间 → 类别、整理格式 → 时间推断 → 目标 → 钱（含人情、留意、值不值、钱和日子）→ 心情、情绪、心情从哪来 → 回顾、周期、提醒 → 关于我 → 发现引擎 → 关于我 2.0 全部；**规则里的常量（天数、门槛、上限）只有一份**，由 TS 生成 Swift 常量，不手抄
- **自验收**：对拍报告——多少个函数、多少份标准答案、**0 处意外不同**（有意不同的逐条写理由）；移植网页版对应的单元测试；性能：关于我主页 ≤ 150 毫秒、发现引擎 ≤ 300 毫秒
- **产品主人验收**：读一页大白话的对拍摘要；开发菜单里看到「演示数据里埋的 5 条真规律都找到了，假的一条没报」

### M4 AI 网关和整理
- **目标**：商业版的 AI 能力在国内云上跑起来，准确率不低于网页版
- **范围**：网页版整理流水线改成纯函数（给背景、回改动，见 AI 方案 3.2）；网关服务（用 Apple 登录换令牌、App Attest、按用户额度、模型路由和备用、日志不含原话）；部署到国内云的测试环境；评测在网关上跑
- **自验收**：全量评测 ≥ 99.9%（和重构前同一天对比，每个维度不降）；耗时中位数和九成线；每段成本；100 个并发压测不出错；自动检查日志里没有原话
- **产品主人验收**：读评测报告摘要；在测试 App（简陋界面即可）里发 5 句话，看到正确的收据

### M5 倾倒（输入、收据、追问、纠正）
- **目标**：「随手说一句就记下」在手机上比电脑上更顺
- **范围**：倾倒栏（打字、按住说话、标记文字）；发送流程（本地先存 → 整理中 → 收据凝结）；离线排队；收据面板；追问条；说一句就改、点卡片改；撤销；招牌动效「倾倒 → 凝结」
- **自验收**：评测里抽 30 句在真机上整理，结果和网关评测一致；30 段真实中文录音的字错率 ≤ 8%；飞行模式记 5 句、联网后全部自动整理；发送到原话出现 ≤ 100 毫秒；设计审查
- **产品主人验收脚本**：打字说 3 句、按住说 2 句、开飞行模式说 1 句再关掉、纠正 1 次、撤销 1 次

### M6 今天（生活画布）
- **范围**：时间轴、一句话总结、目标进度条、记录详情（改、删、看原话、看版本历史）、左右滑换日子、空状态
- **对照**：SPEC 第七章逐条
- **自验收**：一天 100 条记录滚动掉帧 < 5 毫秒/秒；对照表全勾
- **产品主人验收**：翻 3 天；改一条、看历史；删一条再撤销

### M7 回顾和提醒
- **范围**：每日回顾（数字由 PourCore 算，那几句由 AI 写、程序核对）、周报月报、连着几天心情不好时那一句；系统通知（早上、晚上、预警、睡前；免打扰；每类每天最多一次；好几天没记会自己变少）；通知设置
- **自验收**：回顾数字对拍；通知时间表测试（跨时区、免打扰、退让规则）；AI 句子里的数字全部核对过
- **产品主人验收**：看昨天的回顾、上周的周报；第二天早上收到一条通知

### M8 钱
- **范围**：钱的全部（本月、月历、一天的钱、列表和搜索、留意的、一样东西的那一页、值不值、报销和借出、人情往来、钱和你的日子），金额可遮住
- **自验收**：钱的全部函数对拍；评测里钱的用例全过；演示数据检查里钱的各项
- **产品主人验收**：按脚本看本月、点一天、遮住金额、看人情往来

### M9 关于我
- **范围**：关于我三期全部（方块图、时间去向、新发现和反馈、四个角度、配方、变化、说的和做的、Pour 认识的、领域页、心情、人、你说的话、主题的起落、你的一年）；端侧向量（主题归堆、按意思搜索共用）
- **自验收**：演示数据检查里关于我的各项全过；主题归堆和网页版一致（同样的向量 → 同样的堆）；页面性能达标
- **产品主人验收**：用演示数据逛一遍；点一条发现回到那几天的原话

### M10 目标
- **范围**：说一句就立目标、进度、各种目标类型、AI 建议的目标等你确认、完成型目标「读完了吗」
- **自验收**：目标函数对拍；评测里目标用例全过

### M11 搜索和原话
- **范围**：搜索标签：关键词（SQLite 全文索引，支持中文）+ 按意思；全部原话按日子浏览；好时刻；感悟；搜索结果点开原话
- **自验收**：1 万段里搜索 ≤ 100 毫秒；网页版的搜索测试用例对拍

### M12 问答
- **范围**：问答循环在手机上（工具查本机数据，网关只转发模型调用、流式返回）；答案带来源和图；数字由程序核对；在倾倒栏里直接问
- **自验收**：问答评测 48 条用 `pour-cli` 在 Mac 上跑，**不低于现在的 100%**；首字中位数 ≤ 1.5 秒
- **产品主人验收**：问 5 个问题（脚本里给），点答案里的来源

### M13 账号、订阅、同步、搬家
- **范围**：用 Apple 登录；付费页和订阅（StoreKit 2，诚实的付费页）；iCloud 同步；导出（Markdown + JSON 开放格式）；**从网页版搬家**；Face ID 锁；隐私中心（什么发出去了、发给谁、存多久）；删除账号（苹果要求）；用户协议和隐私政策；AI 服务公示（模型名称、备案号）；AI 生成内容标识
- **自验收**：两台设备同步 20 个场景（同时改、离线改、删了又改……）全过；搬家：用网页版导出包逐表对数（只对数，不看内容）；沙盒环境付费全流程（买、续、退、恢复、过期）；删除账号后网关里没有这个人
- **产品主人验收**：在自己手机上登录、试用 Pro、把网页版的数据搬过来、对一下条数

### M14 系统集成
- **范围**：小组件（今天一句话、快速倾倒、心情像素）；锁屏小组件；App Intents（Siri「倾一下」「今天怎么样」、快捷指令）；分享扩展（从微信、浏览器分享文字进来）；控制中心按钮；聚焦搜索（默认只索引标题，原话要用户打开）
- **自验收**：每个入口都能在 3 秒内完成一次记录；隐私：系统索引里默认没有原话

### M15 打磨和硬化
- **范围**：用 Instruments 全面过一遍性能；旁白全程走查；内存泄漏；崩溃和卡顿测试；安全检查（数据保护、钥匙串、传输安全、证书固定）；极端数据（3 年、超长一段话、上千个类别）；省电
- **自验收**：性能预算全部达标；内测前崩溃率 < 0.2%

### M16 内测和上架
- **范围**：TestFlight 公测（几十到几百人）；App 内「反馈」（可选附诊断信息，不含原话）；App Store 的中文介绍、截图、预览视频（用演示数据自动生成）；隐私标签；审核说明和演示模式；ICP 备案号和 AI 公示；分阶段发布（7 天）
- **自验收**：上架清单逐条（见 07 第 7 节）
- **产品主人验收**：看商店页预览；决定发布日期

## 7. 每个模块里 Claude 的固定动作

1. 开 `feature/ios-mX-名字` 分支；写模块小方案，等确认
2. 先写测试（对拍、单元、界面），再写实现
3. 新组件先进设计画廊；页面只用设计系统
4. 每天结束：本地全部检查通过才推送
5. 做完：自验收（跑全部检查、真机走脚本、截图过审查清单、量性能）→ 写自验收报告 → 推 TestFlight → 通知产品主人验收
6. 验收通过：合并、打标签、更新能力对照表和 CHANGELOG

## 8. Mac 上怎么开工（产品主人照着做）

## 9. 环境

| 环境 | 网关 | 用途 |
|---|---|---|
| 本机开发 | Mac 上跑网关（`npm run gateway:dev`） | 开发、单元和界面测试（用假的大模型） |
| 测试环境 | 国内云的一套小网关 | TestFlight 内测、评测、压测 |
| 正式环境 | 国内云，可以横向扩 | App Store 用户 |

App 有三个构建配置（开发 / 测试 / 正式），分别连三个网关；正式版的 Bundle ID 固定不变（它绑着备案）。
