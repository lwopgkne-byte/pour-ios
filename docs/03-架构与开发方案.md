# 03 架构与开发方案

> 依据：[00-提示词](00-提示词.md)。v1.1（2026-10-17）：按产品主人的要求，**架构为 iOS 重新设计**——从手机、离线、多设备、商业规模出发，不从网页版的结构出发；网页版能用的就用（第 2 节），不能用的逐条想办法。
> AI 部分细节见 [04](04-AI能力与程序适配方案.md)，测试见 [05](05-测试方案.md)，仓库和发布见 [07](07-代码管理与发布.md)。

---

## 1. 架构原则

| # | 原则 | 意思 |
|---|---|---|
| 1 | **手机是数据的家** | 数据在设备上；除了 AI 整理和问答，全部离线可用；云只做两件事：AI 理解、跨设备同步 |
| 2 | **原话是源头，结构可以重来** | 原话是事实：你可以改错字（语音常听错），但每一次改动都留在历史里，改完按新的重新整理；记录是对原话的理解——换了模型、改了规则，也可以拿原话重新整理 |
| 3 | **一段话 = 一个改动包** | AI 理解一段话的结果是一个「改动包」：整体应用、整体撤销、整体追溯 |
| 4 | **说出来的存，算出来的不存** | 只存用户产生的东西（原话、记录、纠正、标记、AI 写的回顾文字）；统计、发现、关于我都从记录现算（带缓存） |
| 5 | **规则只有一份** | 确定性的规则只在 `PourCore` 里；任何页面、任何功能都调用它，不各写一套 |
| 6 | **网关不记得你说过什么** | 网关不存用户内容；模型、提示词、把关规则随时可换，不用发 App |
| 7 | **能换的都留好接缝** | 同步引擎、AI 后端、模型、语音、向量都藏在协议后面，以后换实现不动业务 |

## 2. 复用地图：能用的用，不能用的想办法

| 网页版的部分 | 结论 | 在 iOS 架构里 |
|---|---|---|
| 规则和算法（`shared/src`：发现引擎、钱、目标、关于我、回顾、时间推断……约 8,600 行） | **沿用**：移植到 Swift，和网页版对拍 | `PourCore`；它的输入输出和网页版一一对应，**存储另行设计**（第 4 节），两者之间用转换层 |
| AI 流水线、Skill、程序把关（`server/src/ai`、`skills/`） | **沿用**：改造接口 | 网关；从「直接读写数据库」改成「背景包进、改动包出」的纯函数 |
| 评测集、判分、训练场 | **沿用** | 开发工具，留在仓库；网关和 `pour-cli` 都用 |
| 演示数据生成器 | **沿用**：移植到 Swift | App 内「看看示例」；TS 版做对拍基准 |
| 产品理念、设计原则、文案禁用词 | **沿用并升级** | 设计宪法、设计规范 |
| 数据库结构（自增编号、单用户、不带时区、人名是字符串） | **重新设计** | 新的领域模型：UUID、时区、人和地方是一等公民、原话位置精确到字 |
| 读写数据库的服务层、路由 | **重新设计** | App 内的应用服务 + 仓储层；网关只有几个接口 |
| 网页界面（React） | **重新设计** | SwiftUI + 设计规范 |
| 提醒（服务器定时 + Server酱 / Bark） | **重新设计** | 手机上算时间表、本地通知、后台任务 |
| 按意思搜索（Node 里跑模型） | **重新设计（同一个模型）** | 端侧模型；向量只在本机 |
| 页面实时同步（SSE） | **不需要** | 本机数据库观察 + iCloud 同步 |
| 局域网 PIN、自动备份、密钥设置 | **不需要** | Face ID、iCloud、网关代管模型 |
| 夜里自动检查 | **改造** | 后台任务把当天的记录交给网关的检查技能 |
| 周报月报的定时任务 | **改造** | 打开时或后台任务里：数字本机算，那几句话请网关写 |
| 网页版的真实数据 | **不迁移** | 从来没有真正的用户，iOS 版从零开始 |

## 4. 领域模型（为 iOS 重新设计）

### 4.1 实体

| 实体 | 是什么 | 关键字段 | 和网页版比 |
|---|---|---|---|
| **原话** `Note` | 你说的一段话 | 文字、说话的时刻、**时区**、所属的一天（按日界线）、来源（键盘 / 语音 / 分享 / 小组件 / Siri）、整理状态；改错字时旧文字进「原话历史」 | 加了时区和来源；改原话有完整历史，改完重新整理这段话（产生新的改动包，旧的记录按改动包替换） |
| **记录** `Fact` | 从原话整理出的一件事 | 种类（事件 / 心情 / 感悟 / 待办）、领域和类别、标题、时间（起止、时区）或只有日子、时长、数量和单位、把握程度、状态（正常 / 待确认）、种类专属内容 | 同一张表 + 种类专属内容，和网页版的结构能一一转换 |
| **钱** `MoneyLine` | 一笔钱（一条记录可以有几笔） | 金额（以分存整数）、方向（花出 / 收入）、标记（报销、借出、还回、到账、退款）、东西、给谁（人）、固定扣款系列、值不值的原话 | **新的一等公民**：网页版藏在记录的「数量」里；钱的页面查询快、规则清楚 |
| **人** `Person` | 你说到的一个人 | 显示名、**多个称呼**（老婆 / 媳妇 / 爱人）、关系、确认状态 | **新的一等公民**：网页版是记录里的字符串、每次现数；一个人几种叫法合并（网页版的待办）在结构上就解决了 |
| **地方** `Place` | 你去的地方 | 名字、多个叫法（「老地方」）、确认状态 | **新的一等公民** |
| **类别** `Category` | 生活领域和子类别 | 名字、符号、领域色、上级、计量方式、同义词 | **基础类别用固定编号、数据库约束不许有上级**（网页版出过「学习」被挂到「睡眠」下面的事） |
| **来源** `Provenance` | 记录来自原话的哪一段 | 记录、原话、**字的起止位置**、那段文字、动作（新建 / 修改 / 删除） | 加了精确位置：原话追溯能直接荧光高亮那一段 |
| **改动包** `ChangeSet` | 一次理解或一次手动改的全部改动 | 来源（理解 / 手动 / 纠正 / 撤销）、对应的原话、改动清单、应用时刻、是否已撤销 | **新**：撤销就是应用它的反向改动；只追加，不修改 |
| **版本** `Revision` | 记录每一次变化后的样子 | 记录、快照、原因、所属改动包、时刻 | 同网页版，只追加 |
| **追问** `Question` | AI 等你回答的一个问题 | 原话、记录、问题、选项、状态 | 网页版是记录上的字段；独立出来更清楚 |
| **目标** `Goal` | 你立的目标 | 同网页版（类型、周期、绑定的类别和关键词……） | 同 |
| **说法** `Saying` | 你的说法（「168 = 16:8 轻断食」） | 说法、意思、从哪段话学到、确认状态 | 同网页版的个人词典 |
| **标记** `Mark` | 你对「关于我」各条的「对 / 不对 / 不用列出」、对新发现的「说中了…」 | 对象、标记、时刻 | 同 |
| **回顾** `Review` | 每天、每周、每月的回顾 | 种类、时段、程序算的数字（快照）、AI 写的句子、用的技能版本、看过没有 | 同网页版的回顾和报告 |
| **主题名** `ThemeName` | AI 给一堆话起的名字 | 代表那段话的编号、名字 | 同 |

### 4.2 存什么、同步什么

| 数据 | 存 | 同步到 iCloud |
|---|---|---|
| 上表全部实体 | 存 | 同步 |
| 全文索引、向量 | 存（本机） | **不同步**（每台设备自己算） |
| 统计、发现、关于我的计算结果 | 只缓存（数据一变就失效） | 不同步 |
| 通知时间表 | 只在本机 | 不同步（每台设备自己排） |
| 设备上的偏好（亮暗、开关） | 本机 | 不同步 |
| 跨设备的设置（日界线、提醒偏好） | 存 | 同步 |

### 4.3 同步冲突怎么处理

| 实体 | 规则 |
|---|---|
| 改动包、版本、原话历史 | 只追加、不修改 → **不会冲突** |
| 原话（改错字） | 两台设备都改了同一段：以后改的为准，另一份进原话历史 |
| 记录、钱、人、地方、目标 | 以修改时间为准整条覆盖；被覆盖的那份进版本历史，记录详情里看得到 |
| 基础类别 | 固定编号，两台设备天然一致 |
| AI 新建的类别、人、地方 | 两台设备离线各建了一个同名的 → 同步后按名字和称呼自动合并 |
| 删除 | 「墓碑」同步；版本历史保留 |

## 5. 关键流程

### 5.1 倾倒 → 理解 → 应用（最重要的一条）

```
你按发送
① 本机：写入原话（状态：排队）→ 放进「待整理」队列；界面 100 毫秒内显示原话（整理中）
② 理解服务（后台）：取出原话，拼背景包——今天和昨天的记录、类别、人和地方、说法、
   进行中的目标、最近几轮对话、等你回答的追问（典型 ≤ 8 KB）
③ 网关：意图识别 → 整理 → 程序把关 → 返回改动包
④ 本机：校验改动包（引用的编号都在、种类和字段对）→ 一个事务全部写入：
   记录、钱、人和地方、来源、版本、追问、改动包本身 → 原话状态：已整理
⑤ 界面：数据库变化自动推到页面；凝结动效；成功触感
⑥ 之后：受影响的缓存失效（今天、钱、关于我）；重排提醒；给新原话补向量
出错：没网 → 留在队列，联网自动重试（同一个原话编号，网关不会重复整理、不会重复扣额度）
      模型出错 → 重试一次 → 标「没整理成」，可以手动再试
```

### 5.2 纠正
- **点卡片改**：生成一个「手动」改动包，不经过 AI；版本原因「手动」
- **说一句改**（「刚才那个是 38 不是 28」）：当成一段原话走 5.1，网关返回的改动包里引用已有记录的编号；版本原因「纠正」；后台再判断这是通用的错还是你个人的说法，个人说法记进「你的说法」

### 5.3 撤销
应用改动包的反向改动，生成一个「撤销」改动包；记录回到原样，版本历史里看得到撤销。

### 5.4 问答
问答循环在手机上：网关加上系统提示词、转发模型调用（流式）；模型要查数据时，手机上的工具查本机数据库（调用 `PourCore` 的同一套规则），把结果交回；数字由手机核对、来源由手机附上。发给模型的只有问题和查出来的那几条。

### 5.5 提醒
- `PourCore` 里的提醒规划器（纯函数）：按设置、目标、作息算出接下来 3 天该发的通知（免打扰、每类每天最多一次、好几天没记会自己变少——网页版的规矩全部沿用）
- 用系统本地通知排上；**iOS 每个 App 最多同时排 64 条本地通知**，所以只排近 3 天，每次打开 App 和后台刷新时补排
- 早上的回顾：后台刷新时提前算好数字、请网关写好句子，到点直接显示

### 5.6 同步
SQLiteData 的同步引擎（基于 CloudKit）；同步进来的改动和本机改动一样走数据库观察刷新界面；合并后按 4.3 处理重复的类别、人、地方。

### 5.7 离线
除了整理和问答，全部离线可用；待整理的原话在时间轴上标「等网络」；网络恢复后按顺序整理。

## 6. App 内部结构

### 6.1 包和依赖

| 包 | 内容 | 能依赖 |
|---|---|---|
| `PourCore` | 领域值类型、全部规则和计算、格式化、提醒规划器 | 只有 Foundation |
| `PourData` | 表结构、迁移、仓储（读写接口）、同步、PourCore 值类型和表之间的转换 | PourCore |
| `PourAI` | 网关客户端、理解服务、问答循环和工具、端侧语音、端侧向量 | PourCore、PourData |
| `PourDesign` | 设计令牌、组件、图表、动效、触感 | 只有 SwiftUI |
| `PourPlatform` | 通知、后台任务、钥匙串、Face ID、小组件和 Siri 的共享部分 | PourCore、PourData |
| `Features/*` | 今天、回顾、关于我、钱、目标、搜索、设置、倾倒、示例……一个功能一个包 | 以上全部，**功能包之间不互相依赖** |
| `App` | 入口、标签栏、导航、依赖装配、远程开关 | 全部 |

CI 检查依赖方向，违反就不能合并。

### 6.2 写法
- 页面只读「界面模型」；界面模型用 `@Observable`，在主线程
- 数据库读用连接池（并发读）、写串行；页面直接观察数据库查询（数据一变自动刷新）
- 重计算（发现引擎、关于我、你的一年）放后台、可取消；结果按「数据版本」缓存
- 依赖注入用 `swift-dependencies`：每个服务都有测试替身（假网关、假语音、假时钟）
- 日志用系统日志，原话标为私密（不会出现在诊断信息里）；性能用系统日志标记
- **开发菜单**（只在开发和测试版本里）：切示例数据、切假网关、性能浮层、手动触发后台任务

## 7. 网关架构

| 模块 | 做什么 |
|---|---|
| 登录 | 用 Apple 登录换短期令牌；**App Attest** 证明请求来自真的 Pour（防止有人盗用网关刷 AI 费用） |
| 额度 | 按用户、按天、按月计数和封顶（Redis）；到了上限排队到第二天并告诉用户 |
| 理解流水线 | 网页版的整理流水线（纯函数化）：意图 → 整理 → 把关 → 改动包 |
| 技能 | 回顾、报告、总结、主题起名、夜里检查：渲染 Skill、校验输出 |
| 问答转发 | 加系统提示词、转发、流式返回、计量 |
| 模型路由 | 主模型、备用模型、超时和熔断；模型名只在网关配置里 |
| 内容安全 | AI 生成的文字给用户看之前过一道检查 |
| 用量统计 | token、耗时、成功率、成本；**日志只有字段白名单，没有原话** |
| 远程开关 | 新功能分批打开、出问题一键关 |

- 无状态，横向扩；只存账号、设备、用量（Postgres）和计数器（Redis），**不存任何原话和记录**
- 接口：`/v1/session`（登录）、`/v1/understand`（理解）、`/v1/skills/{名字}`、`/v1/qa`（流式）、`/v1/config`、`/v1/usage`、`/v1/account`（删除）
- 部署在国内云，两个可用区，轮流更新；容量估算见 AI 方案第 5 节

## 8. 技术选型（每条在 M0 写成 ADR）

| # | 方面 | 选择 | 为什么 | 没选的和原因 |
|---|---|---|---|---|
| A1 | 语言 | Swift 6（严格并发检查） | 编译期发现数据竞争 | — |
| A2 | 界面 | SwiftUI 为主；倾倒栏的输入区用 UIKit 包一层 | 系统组件、玻璃、动效都是 SwiftUI 优先；中文输入法的标记文字、输入框长高用 UIKit 控制更稳 | React Native / Flutter：拿不到最好的原生手感和系统新能力 |
| A3 | 最低系统 | iOS 26，用 iOS 27 SDK 构建 | 苹果 2026 年 6 月统计：能升级的 iPhone 79% 已装 iOS 26；端侧中文语音、Liquid Glass 都要 26 | — |
| A4 | 架构 | 分层 + 单向数据流；`@Observable` + `swift-dependencies` | 轻、好测、好维护 | TCA：样板多，这个规模不划算 |
| A5 | 数据库 | SQLite + GRDB；界面观察和同步用 SQLiteData | 复杂查询最直接、最快；规则能用数据库约束守住 | SwiftData：复杂查询和迁移不可控 |
| A6 | 同步 | CloudKit 私有库（SQLiteData 同步引擎），同步层可替换 | 数据在用户自己的 iCloud；我们不碰；免费 | 自建同步：要存用户日记；以后做安卓时再加端到端加密同步 |
| A7 | 规则和计算 | `PourCore` 纯 Swift 包，iOS 和 macOS 都能跑 | 移植 + 对拍；能在 Mac 命令行跑评测和对拍 | 在手机里跑 JavaScript：两套语言、桥接开销 |
| A8 | AI 网关 | TypeScript（Node 22 + Fastify），国内云 | 沿用整理流水线、Skill、把关和评测，准确率原样继承；改提示词不用等审核 | 用 Swift 重写流水线：要重新赚回 99.9%，没收益 |
| A9 | 账号 | 用 Apple 登录 + 短期令牌 + App Attest | 摩擦最小、防盗刷 | 只用令牌：可以被抓包盗用 |
| A10 | 通知 | 本地通知为主，手机上排时间表 | 不依赖服务器、私密、省电 | 服务器推送：要知道你的作息 |
| A11 | 语音 | SpeechAnalyzer（端侧中文），不达标退回系统听写 | 录音不出手机 | 云端识别：要上传录音 |
| A12 | 按意思搜索 | bge-small-zh 转端侧模型（Core ML；iOS 27 起可用 Core AI），向量存本机 | 网页版验证过中文效果；端侧不花钱、不出手机 | 系统句向量：中文支持不确定 |
| A13 | 全文搜索 | SQLite FTS5 的三字切分处理 3 个字以上的搜索；**1–2 个字的搜索**（「跑步」「加班」，中文里最常见）直接扫描原话 | 两条路加起来 1 万段里 ≤ 100 毫秒（扫描 1 万段只要几毫秒） | 只用三字切分：两个字的词搜不到；自己写全部子串搜索：大数据时慢 |
| A14 | 图表 | Swift Charts + `Canvas` 自绘 | 原生、无障碍、动画好 | 网页图表库：不原生 |
| A15 | 工程生成 | XcodeGen（`project.yml`） | 工程文件不再合并冲突 | 手改 `.pbxproj` |
| A16 | 代码风格 | SwiftLint + swift-format；令牌检查是自定义规则 | 自动守住设计规范 | — |
| A17 | 观测 | MetricKit + 系统日志标记 + Xcode Organizer；网关用云监控 | 不引入拿用户数据的第三方 SDK | 第三方崩溃收集：以后视需要再评估 |
| A18 | 依赖政策 | 能用系统的不用第三方；每个第三方库写 ADR | 少依赖、少风险 | — |
| A19 | 多语言 | 界面文字全进 String Catalog，简体中文为基准 | 以后加语言只加翻译 | 文字写死在代码里 |

## 9. 性能预算

基准机 **iPhone 13**；数据：示例 9 周 + 合成 3 年（约 1.1 万段话）。自动测试 + 真机量，不达标不能验收。

| 指标 | 预算 |
|---|---|
| 冷启动到能输入 | ≤ 400 毫秒 |
| 热启动 | ≤ 150 毫秒 |
| 按发送 → 原话出现 | ≤ 100 毫秒 |
| 按发送 → 收据出现 | 中位数 ≤ 3 秒、九成 ≤ 6 秒（期间有进度） |
| 滚动掉帧 | < 5 毫秒/秒；高刷屏 120 帧 |
| 关于我主页计算 | ≤ 150 毫秒（9 周）；≤ 400 毫秒（3 年，后台，先显示缓存） |
| 发现引擎一次全量 | ≤ 300 毫秒（9 周） |
| 搜索 | ≤ 100 毫秒（1 万段） |
| 问答首字 | 中位数 ≤ 1.5 秒 |
| 内存 | 常态 ≤ 150 MB |
| 安装包 | ≤ 60 MB（向量模型首次需要时再下载） |
| 后台耗电 | 每天后台任务合计 ≤ 30 秒 |

## 10. 模块计划

每个模块：**目标 → 范围 → 自验收标准 → 产品主人验收要点**。开工前写成模块小方案（`docs/ios/模块/Mx-名字.md`），确认后再做。

### M0 开工准备
- **目标**：整条流水线打通——仓库里的代码自动构建、测试、装到产品主人的手机上
- **范围**：Mac 一键环境脚本；XcodeGen 工程和分层的包骨架；只有启动页的空 App；Xcode Cloud（推送 → 构建 → 测试 → TestFlight 内部测试）；GitHub Actions（网关和 TS）；ADR A1–A19；**能力对照表**（从 SPEC 和各 PRD 逐条整理）；对拍标准答案导出脚本；Bundle ID 定下来
- **自验收**：CI 全绿；干净的 Mac 照 README 15 分钟装好环境；空 App 在真机上打开
- **产品主人验收**：收到 TestFlight 邀请，装上，看到启动页

### M1 设计系统
- **目标**：视觉方向在真机上定下来；全部组件准备好
- **范围**：设计规范 01–12 落成 `PourDesign`（令牌、组件、图表基础、动效、触感）；设计画廊 App；**真机样张 5 屏**（今天、收据、关于我、钱、回顾，亮暗各一，用示例数据静态渲染）；App 图标三个方案；令牌检查、对比度测试
- **自验收**：设计审查清单全过；截图矩阵全部看过
- **产品主人验收**：翻画廊和样张；拍板 D10；选 App 图标 → **锁定令牌 v1**

### M2 领域模型和数据层
- **目标**：第 4 节的领域模型落地；手机上有一个能翻的示例人生
- **范围**：表结构（含约束：基础类别不许有上级、钱以分存整数……）；迁移框架；仓储；PourCore 值类型和表之间的转换层；**示例数据生成器移植**（9 周那个人）；新增「一整年」示例；「看看示例」用的独立数据库；同步先不开
- **自验收**：9 周示例在 iPhone 13 上生成 ≤ 1 秒；和网页版对拍：同一个「今天」每天的原话和记录一致；约束测试（试图把基础类别挂到别处会被拒绝）
- **产品主人验收**：开发菜单切到示例，在简单列表里翻原话和记录

### M3 规则和计算（PourCore）
- **目标**：网页版的全部规则移植到 Swift，算出来一模一样
- **范围**：按依赖顺序——日期时间 → 类别 → 时间推断 → 目标 → 钱 → 心情 → 回顾、提醒 → 关于我 → 发现引擎 → 关于我 2.0；规则常量由 TS 生成，不手抄
- **自验收**：对拍报告 **0 处意外不同**；移植对应的单元测试；关于我 ≤ 150 毫秒、发现引擎 ≤ 300 毫秒
- **产品主人验收**：读一页大白话的对拍摘要；开发菜单里看「示例里埋的 5 条真规律都找到了，假的一条没报」

### M4 AI 网关和理解
- **目标**：AI 能力在国内云上跑起来，准确率不低于网页版
- **范围**：整理流水线纯函数化（背景包 → 改动包）；网关第 7 节的各模块；测试环境部署；评测在网关上跑；手机端理解服务（队列、背景包、应用改动包）
- **自验收**：全量评测 ≥ 99.9%（和重构前同一天对比，各维度不降）；耗时中位数和九成线；每段成本；100 并发压测；日志里没有原话
- **产品主人验收**：读评测摘要；在测试界面里发 5 句话看到正确的收据

### M5 倾倒
- **目标**：「随手说一句就记下」在手机上比电脑上更顺
- **范围**：倾倒栏全部状态（打字、按住说话、标记文字）；发送流程；离线队列；收据；追问；说一句就改、点卡片改；撤销；招牌动效；倾倒栏放在标签栏「底部附件」位置的实测（不行就用自己的浮动栏）
- **自验收**：评测里抽 30 句真机整理，和网关评测一致；30 段真实中文录音字错率 ≤ 8%；飞行模式记 5 句、联网后全部整理；发送到原话出现 ≤ 100 毫秒
- **产品主人验收脚本**：打字 3 句、按住说 2 句、开飞行模式说 1 句再关掉、纠正 1 次、撤销 1 次

### M6 今天
- **范围**：时间轴、一句话总结、目标进度、记录详情（改、删、原话追溯、版本历史）、左右滑换日子、空状态
- **自验收**：一天 100 条记录滚动掉帧 < 5 毫秒/秒；能力对照表全勾
- **产品主人验收**：翻 3 天；改一条看历史；删一条再撤销

### M7 回顾和提醒
- **范围**：每日回顾、周报月报、连着几天心情不好的那一句；提醒规划器和本地通知；后台预先算好早上的回顾；通知设置
- **自验收**：回顾数字对拍；通知时间表测试（跨时区、免打扰、退让规则、64 条上限）；AI 句子里的数字全部核对
- **产品主人验收**：看昨天的回顾和上周周报；第二天早上收到一条通知

### M8 钱
- **范围**：钱的全部（本月、月历、一天的钱、列表和搜索、留意的、一样东西、值不值、报销和借出、人情往来、钱和日子），金额遮住
- **自验收**：钱的全部函数对拍；评测里钱的用例全过

### M9 关于我
- **范围**：关于我三期全部（含你的一年）；端侧向量（主题归堆、按意思搜索共用）；人和地方作为一等公民的页面（一个人几种叫法合并）
- **自验收**：示例检查里关于我的各项全过；主题归堆和网页版一致；页面性能达标

### M10 目标
- **范围**：说一句就立目标、进度、各种目标、AI 建议的目标等你确认
- **自验收**：目标函数对拍；评测里目标用例全过

### M11 搜索和原话
- **范围**：关键词（FTS5）+ 按意思；全部原话按日子浏览；好时刻；感悟
- **自验收**：1 万段 ≤ 100 毫秒；网页版的搜索测试对拍

### M12 问答
- **范围**：问答循环在手机上；工具查本机数据；网关转发和流式；数字核对、来源；倾倒栏里直接问
- **自验收**：问答评测 48 条（`pour-cli` 在 Mac 上跑）不低于现在的 100%；首字中位数 ≤ 1.5 秒

### M13 账号、同步、隐私
- **范围**：用 Apple 登录；iCloud 同步（第 4.3 节的冲突规则）；Face ID 锁；隐私中心（什么存在哪、发给了谁）；导出（Markdown + JSON 开放格式）；删除账号；AI 服务公示和标识
- **自验收**：两台设备同步 20 个场景全过；导出再导入逐表对数；删除账号后网关里没有这个人

### M14 系统集成
- **范围**：小组件（今天一句话、快速倾倒、心情像素）；锁屏小组件；Siri 和快捷指令（「倾一下」「今天怎么样」）；分享扩展；控制中心按钮；聚焦搜索（默认只索引标题）
- **自验收**：每个入口 3 秒内完成一次记录；系统索引里默认没有原话

### M15 打磨和硬化
- **范围**：性能全面过一遍；旁白全程走查；内存泄漏；崩溃和卡顿；安全检查；极端数据（3 年、超长一段话）；省电
- **自验收**：性能预算全部达标；内测前崩溃率 < 0.2%

### M16 内测
- **范围**：TestFlight 公测（几十到几百人）；App 内「反馈」（可选附诊断，不含原话）；根据反馈改
- **自验收**：内测指标达标（总体方案第 2 节）

> 上架（商店素材、审核、合规、付费）等商业的事定下来后再排；见总体方案第 8 节。

## 11. 每个模块里 Claude 的固定动作

1. 开 `feature/ios-mX-名字` 分支；写模块小方案，等确认
2. 先写测试（对拍、单元、界面），再写实现
3. 新组件先进设计画廊；页面只用设计规范
4. 每天结束：本地全部检查通过才推送
5. 做完：自验收（全部检查、真机走脚本、审查清单、性能）→ 写报告 → 推 TestFlight → 通知产品主人
6. 验收通过：合并、打标签、更新能力对照表和 CHANGELOG
