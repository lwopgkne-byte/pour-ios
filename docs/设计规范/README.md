# Pour 设计规范（iOS）

> 设计方案的第二层「设计系统」的完整规范：颜色、字体、高亮、图标、布局、形状和材质、动效和触感、组件、数据可视化、文案、深色和无障碍、交互和页面。
> 上一层是[设计宪法](../02-设计方案.md)（为什么、什么不能做），下一层是[设计审查](../02-设计方案.md#第三层-设计审查)（怎么证明做到了）。
> **版本 v1.0（2026-10-17）**。数值跟着视觉方向 D10「纸·墨·青」走；产品主人看完 D10 若要调整，只改「原始色板」，语义令牌和组件规范不动。

## 一句话说清这套规范

**黑白是骨架，青是懂你，荧光是追溯，颜色只给数据。**

| 角色 | 用什么 | 出现在哪 |
|---|---|---|
| 骨架 | 纸（底）、卡（面）、墨（字和一切操作） | 所有界面；按钮、链接、选中、标签栏都是墨色 |
| 懂你 | **青**（品牌色） | 只在 Pour 理解了你的时刻：认出你说的人和地方、新发现、收据凝结、「Pour 认识的」 |
| 追溯 | **荧光**（荧光笔的黄） | 搜索命中的字、原话里对应的那一段 |
| 数据 | 九个领域色、心情五档 | 时间轴的色点、方块图、图表、目标进度——只在数据里 |
| 需要你 | 琥珀 | 落后的目标、等你回答的追问（小点和文字，不铺底） |
| 危险 | 系统红 | 只用于不可恢复的操作（删除所有数据） |

> 从 Manus 学的：用单色的克制做出高级感，靠层级和留白，不靠颜色。从 Pour 自己来的：唯一的品牌色只说一件事——**它懂你**。所以青色每出现一次都有意义。

## 怎么用

- **令牌名就是代码名**：规范里的 `ink`、`space.card`、`motion.snappy` 在 `PourDesign` 包里同名，代码只能用令牌，不能写数值（SwiftLint 检查）
- **新组件先进设计画廊**（Gallery App），全部状态截图过审查，再进页面
- **改规范**：产品主人确认 → 改这里 → 改 `PourDesign` → 截图测试更新基准 → 写进变更记录
- 原始色板由 `ios/scripts/palette.py` 按 OKLCH 生成，对比度测试进 CI；不手调十六进制
