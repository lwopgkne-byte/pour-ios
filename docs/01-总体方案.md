# 01 总体方案：Pour iOS 商业版

> 依据：[00-提示词](00-提示词.md)。本文回答「做成什么样、关键怎么定、按什么顺序做、要多久、风险在哪」。细节见 02–07 各方案。
> 状态：v1.0 定稿（2026-10-17）。第 3 节的 11 个决定待产品主人确认，确认前不做不可逆的事。

---

## 1. 定位

**Pour（倾）是一个你只管说、它帮你理清生活的 App。**
随手说一句——打字、语音、从别的 App 分享进来——它就把这句话整理成结构：做了什么、花了多少钱、心情怎样、和谁在一起、离目标还有多远。用得越久，它越懂你，也让你越来越懂自己。

它同时取代了几类 App，但只有一个输入框：

| 别人要分开装的 | 在 Pour 里 |
|---|---|
| 日记（Day One、Apple 日记） | 你说的每句话都是原话，永远保存 |
| 记账（随手记、鲨鱼记账） | 「午饭 28」就记好了，不用选分类 |
| 时间记录、习惯打卡 | 「跑了 5 公里」就算进目标 |
| 心情记录（Daylio） | 「今天有点烦」就记下心情，不用点表情 |
| 自我分析 | 程序算出「你不知道的你」，每一条都能点回原话 |

**我们赢在三件别人做不到一起的事**
1. **零表单**：别的 App 让你填表，Pour 让你说话
2. **说的是真的**：发现和数字全部由程序从你的原话算出来，AI 只负责措辞——不是 AI 猜你、给你打标签
3. **你的就是你的**：原话存在你的手机和你自己的 iCloud 里；整理时经过我们的服务器，处理完就忘，不保存

## 2. 目标和衡量

| 阶段 | 用户 | 衡量（上线后看） |
|---|---|---|
| 内测（TestFlight） | 几十到几百人 | 闪退率 < 0.2%；第 7 天还在记的人 ≥ 40%；整理准确率 ≥ 99.9% |
| 上线第一年 | 几千到几万 | 第 30 天留存 ≥ 25%；付费转化 ≥ 4%；每个付费用户的 AI 成本 ≤ 收入的 35% |
| 规模化 | 几十万 | 架构不推倒；网关横向扩；单用户成本随缓存命中率下降 |

「越用越懂你」的数字沿用网页版并放在显眼处：每 100 段话里要你改几次、追问几次，越来越少。

## 3. 关键决定（推荐 + 待确认）

下面每一条都给了推荐和理由。**产品主人确认后才开工**；不确认的项按推荐先做准备，不做不可逆的事。

| # | 决定 | 推荐 | 为什么 | 代价 / 备选 |
|---|---|---|---|---|
| D1 | 首发市场 | **中国大陆（简体中文）先上**；海外（繁中、英文）第二阶段 | 用户、语料、评测全是中文；DeepSeek 在国内，数据不出境 | 合规手续多、周期 2–4 个月，**必须马上并行启动**（第 9 节）。备选「先上海外区」能避开备案，但主力用户在大陆，不推荐 |
| D2 | 主体 | **以公司主体**申请苹果开发者组织账号、备案、生成式 AI 登记 | 个人主体在生成式 AI 登记、商业化上会卡住 | 要先注册公司（产品主人办）；具体以属地网信办答复为准 |
| D3 | 最低系统 | **iOS 26** | 苹果 2026 年 6 月的统计：能升级的 iPhone 里 79% 已装 iOS 26，近四年的机型 86%；端侧中文语音（SpeechAnalyzer）、系统材质 Liquid Glass 都要 26 | 放弃 iPhone XS / XR 这一代；iOS 27 的新能力做版本判断再用 |
| D4 | 数据放哪 | **本机为主（SQLite）+ 用户自己的 iCloud 同步（CloudKit 私有库）**；我们的服务器不存原话和记录 | 隐私是日记 App 的命；用户再多，我们的存储成本和泄露风险都接近零 | 以后做安卓、网页同步要另加一套「端到端加密同步」；数据层按「同步引擎可替换」写，到时不重做 |
| D5 | AI 在哪跑 | **整理在我们的网关上跑**（沿用网页版的 TypeScript 流水线和评测）；**问答在手机上跑**（在手机上查数据；只有回答这个问题用得到的那几条，随问题经网关发给模型）；**统计和发现全部在手机上算** | 整理的准确率是网页版花最多心血的地方，原样沿用最稳；提示词和把关规则改了不用等苹果审核；问答要查你的全部数据：在手机上查，发出去的只是查出来的那几条，比把全部数据交给服务器私密得多 | 网页版的整理代码要改成「给什么背景、回什么改动」的纯函数形式（一次性的工作，评测保证不掉） |
| D6 | 账号 | **用 Apple 登录为主**；手机号验证视合规要求加 | 摩擦最小、隐私最好 | 大陆对生成式 AI 用户的实名要求，在办登记时向网信办确认 |
| D7 | 收费 | **免费 + 订阅（Pour Pro）**，见第 8 节 | 统计和发现在手机上算不花钱，可以大方免费；只有 AI 整理花钱，按量设上限 | 价格上线后按真实数据调 |
| D8 | 网页版 | **冻结成「参照版」**：继续能跑、不加新功能 | 它是对拍的标准答案，也是产品主人的过渡工具 | 产品主人的真实数据在 M13 搬进 iOS 版 |
| D9 | 仓库 | **同一个仓库**，加 `ios/` 和 `gateway/` | Skill、评测、标准答案只有一份，不会两边对不上 | 仓库变大；用目录和 CI 隔开 |
| D10 | 视觉方向 | **「纸·墨·青」**（暂名，见设计方案） | 温暖、安静、有识别度，和「倾」的水的意象一致 | M1 出真机样张，产品主人拍板后才铺开 |
| D11 | 大模型 | **DeepSeek V4 Flash 为主**，一个已备案的国内模型做备用（通义千问） | 网页版评测 99.93% 就是它；价格低、缓存命中更便宜 | 模型名称和备案号要在 App 里公示 |

## 4. 总体架构

```
┌──────────── iPhone（数据的家）─────────────┐            ┌────── Pour 网关（国内云）──────┐       ┌── 大模型 ──┐
│ 界面：SwiftUI + 设计系统 PourDesign          │   HTTPS    │ 账号、额度、订阅校验              │       │ DeepSeek   │
│ 规则和计算：PourCore（Swift，对拍网页版）    │ ─────────▶ │ 整理流水线（TypeScript，沿用）    │ ────▶ │ 通义千问   │
│ 本机数据库：SQLite（GRDB）                   │ ◀───────── │ 单技能调用（回顾、报告、起名…）   │ ◀──── │ （备用）   │
│ 端侧：语音转文字、按意思搜索的向量            │            │ 问答转发（工具在手机上执行）       │       └────────────┘
│ 系统：通知、小组件、Siri、分享、Face ID       │            │ 不存原话；只记用量、耗时、错误码   │
└───────────────┬────────────────────────────┘            └──────────────────────────────────┘
                │ CloudKit 私有库（用户自己的 iCloud；中国大陆由云上贵州运营）
                ▼
        以后：iPad、Mac、Apple Watch
```

**三条边界（所有设计都守着它们）**
1. **手机是数据的家**：原话、记录、版本、纠正、关于我，全部在手机上；iCloud 只是同步和备份
2. **网关不记得你说过什么**：它把一段话和必要的背景交给模型、把结果交回手机，处理完就忘；日志里没有原话
3. **能在手机上算的不上网**：统计、发现、钱、目标、搜索、语音转文字，全在手机上

详见 [03 开发方案](03-开发方案.md) 和 [04 AI 方案](04-AI能力与程序适配方案.md)。

## 5. 能力对照：网页版的每一项，在 iOS 上怎么样

「同」= 规则原样继承、对拍保证一致；「升」= 在手机上做得更好；「改」= 换了做法（写了理由）；「去」= 不再需要（写了理由）。

| 网页版能力（SPEC 章节） | iOS | 怎么做 |
|---|---|---|
| 一个输入框（第五、六章） | 升 | 底部「倾倒栏」：打字、按住说话、从别的 App 分享、锁屏小组件、Siri「倾一下」；没网先存，联网自动整理 |
| AI 整理、收据、追问、接着上一句说、说一句就改 | 同 + 升 | 规则和评测原样；收据在原地「凝结」成卡片，能撤销 |
| 生活画布（第七章） | 升 | 「今天」标签：时间轴、一句话总结、目标进度；左右滑切换日子 |
| 目标（第八章） | 同 | 说一句就立目标；进度条在「今天」顶部，详情在目标页 |
| 找东西、问问题（第九章） | 升 | 搜索标签：关键词 + 按意思（端侧）；问答在手机上查数据，答案带来源和图 |
| 看板（第十章） | — | 1.17.0 已并进「关于我」 |
| 笔记库（第十一章） | 改 | 并进搜索标签：全部原话、好时刻、感悟，按日子浏览 |
| 主动提醒与报告（第十二章） | 升 | 系统通知，提醒时间在手机上算好、本地排好，不依赖服务器；免打扰、每类每天最多一次的规矩不变 |
| 回顾（日、周、月） | 同 + 升 | 数字由 PourCore 算，AI 只写那几句；周报月报做成可以分享的长图（可选） |
| 心情 | 同 | 五级说法、精力只在说到时才有、好时刻、心情从哪来 |
| 钱（第一至三期、人情往来） | 同 + 升 | 一级标签；月历、留意的、值不值、人情往来；数字等宽、金额可遮住 |
| 关于我 2.0（三期全部） | 同 + 升 | 一级标签；方块图、新发现、配方、变化、说的和做的、主题的起落、你的一年；图表做成原生的、可以点 |
| 越来越懂你（更懂我的整理） | 同 | 「Pour 认识的你」作为整理背景，看得见、能纠正 |
| 设置与数据（第十三章） | 改 | 账号、订阅、隐私中心（什么发出去了、发给谁）、导出（Markdown + JSON 开放格式）、从网页版搬家、Face ID 锁 |
| 局域网访问、PIN | 去 | 不再需要：App 本身在手机上；PIN 换成 Face ID |
| 每天自动备份 | 改 | iCloud 同步 + 随时导出 |
| 大模型密钥、Server酱、Bark 设置 | 去 | 订阅里含 AI；推送用系统通知 |
| 夜里自动检查（审核员） | 改 | Pro 功能：每晚帮你检查一遍当天的整理，查出的让你点「确实错了 / 没错」 |
| 训练场、评测、AI 准不准 | 改 | 训练场和评测是开发工具，留在仓库；「越来越懂你」的数字留在设置里 |
| 「你改过的地方」用来变准 | 改 | 只在用户主动开启「帮 Pour 变准」后、去掉个人信息才收集（第 9 节、AI 方案） |
| 演示数据 | 升 | App 内「看看示例」（新用户先逛一个人的 9 周）、给苹果审核看、宣传截图；另加「一整年」的演示数据，让「你的一年」也能演示 |

完整的逐条对照表（到每个规则、每个数字）在 M0 生成：`docs/ios/能力对照表.md`，每个模块验收时逐条勾。

## 8. 商业模式和定价（推荐，上线后按数据调）

**原则**：在手机上算的东西不花我们的钱，大方给；只有 AI 整理、问答、每晚自动检查花钱，按量给——**只按真正花钱的东西分档**，主题起名（一周一次、几分钱）、「你的一年」（全是程序算的）都不拿来分档。不做诱导付费的花招（原则：诚实、不打扰）。

| | 免费 | Pour Pro |
|---|---|---|
| 记录、今天、回顾的数字、钱、关于我、目标、搜索 | 全部 | 全部 |
| AI 整理 | 每月 100 段 | 不限（合理使用：每月 3,000 段） |
| 问答 | 每月 20 次 | 不限（合理使用） |
| 回顾和周报月报里 AI 写的那几句 | 有 | 有 |
| 每晚自动检查（用更强的模型复查当天的整理） | — | 有 |
| 价格（中国区） | ¥0 | **¥18 / 月，¥128 / 年**；首次 7 天免费试用 |

**成本账**（网页版实测：每段话整理约 ¥0.008，含多步调用和缓存命中）

| 用户类型 | 每天说几段 | 每月 AI 成本 |
|---|---|---|
| 轻度 | 3 | 约 ¥0.8 |
| 一般 | 6 | 约 ¥1.6（含回顾、问答） |
| 重度 | 20 | 约 ¥5–7（含每晚自动检查） |

- 苹果抽成：中国区 2026-03-15 起，小型企业计划（年收入 100 万美元以下）和订阅满一年后是 **12%**，标准是 25%
- 年付用户月均到手约 ¥9.4（¥128 ÷ 12 × 88%），一般用户成本约 ¥1.6，毛利充足；重度用户靠「合理使用」上限兜底
- 免费用户成本上限约 ¥0.8 / 月；网关按用户、按天设预算，超了就排队到第二天，不会失控
- 价格档位、免费额度上线后按真实转化率和成本调；DeepSeek 的价格以官方页面为准，每季度复核

## 9. 合规路线（中国大陆，D1 确认后马上启动，和 M0–M4 并行）

| 步 | 做什么 | 谁做 | 大约多久 |
|---|---|---|---|
| 0 | **名字和商标**：查「Pour」「倾」在 App Store 中国区是否可用、商标是否被注册（第 9 类软件、第 42 类服务），能注册就尽早注册 | 产品主人（Claude 先查一遍） | 查 1 天；注册 6–12 个月（申请后即可使用） |
| 1 | 注册公司、开对公账户 | 产品主人 | 2–4 周 |
| 2 | 苹果开发者**组织**账号（要邓白氏编码） | 产品主人（Claude 准备材料清单） | 1–2 周 |
| 3 | **定下 Bundle ID**（之后所有备案都绑它，改了要重办） | 一起定 | M0 第一天 |
| 4 | 域名、国内云服务器、ICP 备案（网关用） | 产品主人提交，Claude 准备 | 1–3 周 |
| 5 | **APP 备案**（填 Bundle ID、证书公钥和 SHA-1）→ 拿到备案号填进 App Store Connect | 同上 | 1–3 周 |
| 6 | **生成式 AI 登记**（属地网信办：调用已备案模型的应用走「登记」，不是完整备案；材料含服务说明、安全评估、内容安全措施、和模型方的协议） | 同上 | 按 1–3 个月准备，以属地要求为准 |
| 7 | App 内和商店页**公示**所用模型的名称和备案号；AI 生成的内容加标识（《人工智能生成合成内容标识办法》2025-09-01 起施行） | Claude（M13） | — |
| 8 | 隐私政策、用户协议；心情、健康类信息按**敏感个人信息**处理，单独同意 | Claude 起草，产品主人找律师过一遍 | 2 周 |
| 9 | 等级保护测评（视网关处理的数据和规模，由律师或测评机构判断） | 产品主人 | 视情况 |
| 10 | 软件著作权（App Store 不要求；以后上安卓应用商店、申请政策支持时有用） | 可选 | 1–2 个月 |

**卡点**：第 5、6 步没完成就上不了中国区。所以 M0 一开始就办，M16 前必须到位。

## 10. 风险和对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 合规拖期 | 上不了中国区 | 马上启动；同时准备海外区版本作为后备；每两周看一次进度 |

| 照抄网页版导致手机体验像网页 | 不像一线 App | 每个模块先做交互小方案、过设计审查；验收看真机 |
| 规则移植出错（TS → Swift） | 数字不对 | 对拍：同一份输入，两边结果逐字节比较 |
| 同步冲突、丢数据 | 致命 | 版本历史永远保留；冲突用确定的规则合并；双设备同步测试；导出随时可用 |
| 一个人 + Claude 的工程，进度受验收节奏影响 | 拖期 | 模块小、验收脚本短（10–20 分钟）；后端和合规并行 |
| 苹果审核被拒 | 延期上架 | 提前读审核指南（订阅、隐私、AI 内容、账号删除）；准备审核演示说明 |
| iOS 每年大改 | 返工 | 只用系统组件和公开 API；设计令牌集中管理，换材质只改一处 |
