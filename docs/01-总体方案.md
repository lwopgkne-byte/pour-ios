## 1. 定位

**Pour（倾）是一个你只管说、它帮你理清生活的 App。**
随手说一句——打字、语音、从别的 App 分享进来——它就把这句话整理成结构：做了什么、花了多少钱、心情怎样、和谁在一起、离目标还有多远。用得越久，它越懂你，也让你越来越懂自己。

它同时取代了几类 App，但只有一个输入框：

| 别人要分开装的 | 在 Pour 里 |
|---|---|
| 日记（Day One、Apple 日记） | 你说的每句话都是原话，永远保存 |
| 记账（随手记、鲨鱼记账） | 「午饭 28」就记好了，不用选分类 |
| 时间记录、习惯打卡 | 「跑了 5 公里」就算进目标 |
| 心情记录（Daylio） | 「今天有点烦」就记下心情，不用点表情 |
| 自我分析 | 程序算出「你不知道的你」，每一条都能点回原话 |

**我们赢在三件别人做不到一起的事**
1. **零表单**：别的 App 让你填表，Pour 让你说话
2. **说的是真的**：发现和数字全部由程序从你的原话算出来，AI 只负责措辞——不是 AI 猜你、给你打标签
3. **你的就是你的**：原话存在你的手机和你自己的 iCloud 里；整理时经过我们的服务器交给 AI 服务商，我们的服务器不保存；AI 服务商怎么处理，在隐私中心照实写清（只选不拿用户数据训练的服务）

## 2. 目标和衡量（产品做好的标准）

| 阶段 | 用户 | 衡量 |
|---|---|---|
| 内测（TestFlight） | 几十到几百人 | 闪退率 < 0.2%；第 7 天还在记的人 ≥ 40%；整理准确率 ≥ 99.9%；设计审查清单全过 |
| 上线以后 | 几千到几十万 | 架构不推倒；网关横向扩；单用户成本随缓存命中率下降 |

「越用越懂你」的数字放在显眼处：每 100 段话里要你改几次、追问几次，越来越少。

| 事 | 什么时候要定 | 为什么可以等 |
|---|---|---|
| 首发市场（中国大陆 / 海外） | 内测快结束时 | 产品和语言（先做简体中文）不受影响 |

## 4. 总体架构

```
┌──────────── iPhone（数据的家）─────────────┐            ┌────── Pour 网关（国内云）──────┐       ┌── 大模型 ──┐
│ 界面：SwiftUI + 设计系统 PourDesign          │   HTTPS    │ 登录、设备证明、额度              │       │ DeepSeek   │
│ 规则和计算：PourCore（Swift，对拍网页版）    │ ─────────▶ │ 理解流水线（TypeScript，沿用）    │ ────▶ │ 备用模型   │
│ 本机数据库：SQLite（新的领域模型）           │ ◀───────── │ 技能（回顾、报告、起名…）         │ ◀──── │            │
│ 端侧：语音转文字、按意思搜索的向量            │            │ 问答转发（工具在手机上执行）       │       └────────────┘
│ 系统：通知、小组件、Siri、分享、Face ID       │            │ 不存原话；只记用量、耗时、错误码   │
└───────────────┬────────────────────────────┘            └──────────────────────────────────┘
                │ iCloud 私有库（用户自己的）
                ▼
        以后：iPad、Mac、Apple Watch
```

**三条边界**
1. **手机是数据的家**：原话、记录、版本、纠正、关于我，全部在手机上；iCloud 只是同步和备份
2. **网关不记得你说过什么**：一段话和必要的背景交给模型、结果交回手机，处理完就忘；日志里没有原话
3. **能在手机上算的不上网**：统计、发现、钱、目标、搜索、语音转文字，全在手机上

为什么这样设计、网页版哪些沿用哪些重做，见 [03 架构与开发方案](03-架构与开发方案.md) 第 1、2 节。

## 5. 能力对照：网页版的每一项，在 iOS 上怎么样

「同」= 规则原样继承、对拍保证一致；「升」= 在手机上做得更好；「改」= 换了做法；「去」= 不再需要。

| 网页版能力（SPEC 章节） | iOS | 怎么做 |
|---|---|---|
| 一个输入框（第五、六章） | 升 | 底部倾倒栏：打字、按住说话、从别的 App 分享、锁屏小组件、Siri「倾一下」；没网先存，联网自动整理 |
| AI 整理、收据、追问、接着上一句说、说一句就改 | 同 + 升 | 规则和评测原样；收据在原地「凝结」成卡片，能撤销（一段话一个改动包） |
| 生活画布（第七章） | 升 | 「今天」标签：时间轴、一句话总结、目标进度；左右滑切换日子 |
| 目标（第八章） | 同 | 说一句就立目标；进度在「今天」顶部，详情在目标页 |
| 找东西、问问题（第九章） | 升 | 搜索标签：关键词 + 按意思（端侧）；问答在手机上查数据，答案带来源和图 |
| 看板（第十章） | — | 1.17.0 已并进「关于我」 |
| 笔记库（第十一章） | 改 | 并进搜索标签：全部原话、好时刻、感悟 |
| 主动提醒与报告（第十二章） | 升 | 系统通知，时间表在手机上算好、本地排好；免打扰、每类每天最多一次的规矩不变 |
| 回顾（日、周、月） | 同 + 升 | 数字由 PourCore 算，AI 只写那几句 |
| 心情 | 同 | 五级说法、精力只在说到时才有、好时刻、心情从哪来 |
| 钱（三期、人情往来） | 同 + 升 | 一级标签；钱成为一等公民（每一笔单独存），查得更快 |
| 关于我 2.0（三期全部） | 同 + 升 | 一级标签；人和地方成为一等公民，「一个人几种叫法合并」在结构上就解决了；一年每天一格改成手机一屏看完的 12 个月小日历 |
| 越来越懂你（更懂我的整理） | 同 | 「Pour 认识的你」作为整理背景，看得见、能纠正 |
| 设置与数据（第十三章） | 改 | 不用注册账号；隐私中心、导出（开放格式）、删除所有数据、Face ID 锁 |
| 局域网访问、PIN、自动备份、密钥设置 | 去 | App 本身在手机上；Face ID；iCloud；网关代管模型 |
| 夜里自动检查 | 改 | 后台任务把当天的记录交给网关的检查技能 |
| 训练场、评测、AI 准不准 | 改 | 训练场和评测是开发工具，留在仓库；「越来越懂你」的数字留在设置里 |
| 演示数据 | 升 | App 内「看看示例」；另加「一整年」的示例，让「你的一年」也能看 |

完整的逐条对照表在 M0 生成：`docs/能力对照表.md`，每个模块验收时逐条勾。

## 6. 模块路线

一个模块是一个能独立验收的增量；两道验收都过了，再做下一个。详细范围和验收标准见 [03](03-架构与开发方案.md) 第 10 节。

| 阶段 | 模块 | 做完能看到什么 |
|---|---|---|
| 一 地基 | M0 开工准备 | 一个空 App 从仓库自动构建、装到你的手机上 |
| | M1 设计系统和样张 | 设计画廊 + 关键页面的真机样张 → **你拍板视觉（D10）** |
| 二 最好用的核心 | **M2 说一句 → 今天** | **第一条完整体验**：打字说一句，凝结成卡片，出现在「今天」——真的 AI、真的数据，做到一线水准 |
| | M3 说得更顺 | 按住说话、追问、说一句就改、撤销、没网也能记 |
| | M4 回顾和提醒 | 每日回顾、周报月报、早上的通知 |
| 三 看见自己 | M5 关于我 | 关于我三期全部 |
| | M6 钱 | 钱的全部功能 |
| | M7 目标 | 目标的全部功能 |
| | M8 搜索和原话 | 关键词 + 按意思找；全部原话、好时刻、感悟 |
| | M9 问答 | 问自己的数据，答案带来源和图 |
| 四 随手可用 | M10 系统集成 | 小组件、Siri、分享扩展、控制中心、锁屏 |
| 五 往后排的 | M11 同步和数据 | iCloud 同步、导出、删除所有数据、Face ID、隐私中心 |
| | M12 打磨和硬化 | 性能、无障碍、边界情况、安全 |
| | M13 内测 | TestFlight 公测、按反馈改 |

**为什么这样排**：最好用、最美的产品第一。第二个模块就交出一条完整的体验并打磨到一线水准，不先花几周做看不见的地基；每个模块自己带着它要用的规则（当场和网页版对拍）。同步、导出这些「往后排」。

上架（商店素材、审核、合规、付费）等商业的事定下来后排在 M13 之后。

## 8. 风险和对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 照抄网页版导致手机体验像网页 | 不像一线 App | 架构和交互都为 iOS 重新设计；每个模块先做交互小方案、过设计审查；验收看真机 |
| 规则移植出错（TS → Swift） | 数字不对 | 对拍：同一份输入，两边结果逐字节比较 |
| 中文语音转写质量不稳 | 语音输入体验差 | M3 用 30 段真实录音测字错率；不达标就保留系统听写作为后备 |
| AI 成本失控 | 亏钱 | 网关按人按天封顶；缓存规矩；每周看成本 |
| 同步冲突、丢数据 | 致命 | 原话和改动包只追加；版本历史永远保留；双设备同步测试 |
| 苹果端侧大模型在大陆何时可用不确定 | 端侧 AI 用不上 | 不放在关键路径上，全部有网关兜底 |
| 进度受验收节奏影响 | 拖期 | 模块小、验收脚本短（10–20 分钟） |
| iOS 每年大改 | 返工 | 只用系统组件和公开 API；设计令牌集中管理 |
| 以后上中国区的合规周期长 | 上架晚 | 决定市场后马上办；AI 标识（M4 起）和服务公示的位置（M11）提前做好 |
