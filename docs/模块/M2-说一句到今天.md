# M2 说一句 → 今天 · 模块小方案

> 依据：[03 架构与开发方案](../03-架构与开发方案.md) 第 5、10 节，[04 AI 能力与程序适配方案](../04-AI能力与程序适配方案.md)，ADR A05（数据库）、A08（AI 网关）。状态：**Claude 决定、直接做**（产品主人：方案不看，只看最终结果；**把功能做出来、在自己的 iPhone 15 + iOS 27 上看效果，优先级最高**）。

## 1. 这个模块回答什么

「我说一句，它真的懂吗？」——打字说一句，几秒后凝结成卡片，出现在「今天」：真的 AI、真的数据。全产品的心脏。

## 2. 分三步交，每一步都有能看的

| 步 | 做完你能看到什么 | 里面做了什么 |
|---|---|---|
| **M2a 打一句 → 今天** | 在倾倒栏打一句「早上跑了五公里 中午和小王吃面三十二」，原话马上出现在今天，几秒后收据凝结出两条记录：跑步、吃面 ¥32 · 和小王 | 正式 App 的外壳（标签栏 + 倾倒栏，样张那一套）；本机数据库（原话、记录、改动包）；理解服务（排队、拼背景包、应用改动包）；**AI 网关第一版**跑在这台 Mac 上：意图识别 + 整理（网页版的两份 Skill 原样搬来）→ 程序把关 → 改动包；收据和招牌动效「倾倒 → 凝结」 |
| **M2b 用起来顺** | 点一张卡片看原话（荧光标出是哪一段）和改动历史；左右滑看昨天；今天上面一句话总结；说「刚才那个是 38 不是 28」就改；撤销 | 记录详情、版本历史、日子切换、总结、纠正、撤销 |
| **M2c 整理得和网页版一样好** | 和网页版一样准：同样的一段话整理出同样的记录 | 网页版的全部程序把关（新类别、同义词、领域归类、时间推断、钱的去向……）逐条搬来、和网页版对拍；网页版 340 条整理评测在网关上 ≥ 99.9%；速度达标（收据中位数 ≤ 3 秒） |

## 3. 执行中的决定（Claude 定，2026-10-18）

| 决定 | 理由 |
|---|---|
| **网关先跑在这台 Mac 上**（Node 24 + Fastify，`gateway/`），手机和 Mac 连同一个 WiFi | 不用花钱租服务器；和网页版一样的用法。上架前再搬到国内云（要花钱，到时候问产品主人） |
| **DeepSeek 密钥用产品主人新建的「Pour iOS」那一把**，放在 `gateway/.env`（不进仓库，Claude 不看） | 产品主人 2026-10-18 选的；和网页版分开，好查花费、好作废 |
| **先不做设备证明（App Attest）** | 要加入苹果开发者计划（产品主人暂不加入）；开发阶段网关只认这台 Mac 和同一个 WiFi 里的手机，用一个开发令牌 |
| **网页版的流水线和 Skill 原样搬进 `gateway/`，改成「背景包进、改动包出」的纯函数** | 准确率原样继承（ADR A08）；手机是真正的数据库，网关不存任何东西 |
| **M2a 先搬主干**：意图识别、整理、基础的把关；类别对不上的先归「其他」 | 先让整条路通、看得到效果；细致的把关在 M2c 一条一条搬、一条一条对拍 |
| **本机数据库用 GRDB**（ADR A05），引进时在 A05 补版本和许可证 | 已定的方案 |
| 接口契约（背景包、改动包）写成带版本号的 JSON Schema（`gateway/contract/`），手机和网关两边都用它测 | 03 第 8 节 |

### M2a 做的时候定的（Claude，2026-10-18）

| 决定 | 理由 |
|---|---|
| **刚说的话以收据出现在时间轴最后**：还在整理、没整理成、整理好不到 10 分钟的；过了 10 分钟，它的记录回到时间轴上自己的位置 | 规范 12「收据就地出现在时间轴上」；看着它凝结时不跳来跳去，回头再看时时间轴是按钟点排好的一天 |
| **空闲的倾倒栏右边是「写」的图标，不是话筒**；整条栏一点就能打字 | 录音在 M3 才接上：放一个点了没反应的话筒不如不放；M3 换回话筒 |
| **倾倒栏的字号封顶在 xxxLarge，更大的字号长按看大字** | 标签栏附件的高度由系统定、不随字号长高（M1 在 iPhone 15 最大字号下实测被切掉一截）；和系统标签栏同一个做法 |
| **M2a 不放撤销条；追问只显示问题、不给选项** | 撤销和回答追问都要「改动包反着来」「带着对话再整理」，M2b 一起做；不放点了没用的按钮 |
| **设置里只有「关于」**：版本号、AI 网关连没连上、密钥能不能用（从「今天」左上角的头像进） | 验收时对得上构建号；整理不动时一眼看出是不是网关没开 |
| **记录的开始、结束存「本地时刻」（YYYY-MM-DDTHH:mm）**，不是只存钟点 | 和网页版一样：跨零点的睡眠结束在第二天，只存钟点分不清；网页版的时间推断（resolveEventTime）原样搬进网关，测试照搬 |
| **预置类别只有一份**：`Packages/PourKit/Sources/PourData/Resources/categories.json`，手机建库和网关的测试都读它 | 两边永远一致；颜色按规范 01 第 3.1 节「默认给」（运动苔、睡眠藤、饮食杏、学习麦、工作湖、其他石） |
| **App 的界面测试用假网关**（启动参数 `-uiTest`，只在 Debug 版里）：不连网、不花钱、结果每次一样 | 真的 AI 由我在模拟器上手动走、截图留证；网关自己的测试用假大模型 |

### M2b 做的时候定的（Claude，2026-10-18）

| 决定 | 理由 |
|---|---|
| **接口契约升到 v2**：背景包带上最近的对话（一小时内、最多 4 段）；改动包除了新建，还有改（改完的样子）、删、之前已记过、要问你的话 | 回答「对」「刚才那个」时 AI 才知道指的是哪条（网页版 dialogue.ts 的教训）；网关照旧是纯函数，改完的样子由它算好，手机整体写入 |
| **每一次改动都留着改之前的样子**（`entryVersion` 表）：撤销、改动历史都照它来；删掉的记录留着（软删除），能撤销 | 「撤销而不是确认」（规范 12）；详情里看得到这条是怎么来的、改过几次 |
| **撤销条 5 秒，只撤刚整理好的那一段话**；撤销以后原话留着，标「已撤销 · 原话还在」 | 后面的话可能又改了同一条，撤更早的会乱；原话是你的，不跟着撤 |
| **追问是「…吗？」时给「对 / 不对」两个选项**，点一下就当作说了这一句；别的追问直接再说一句 | 选项走和打字同一条流程（带着对话再整理），不另写一套 |
| **删除不靠猜**：AI 拿不准删哪条（带着追问、或把握不到 0.6）先问，不删 | 网页版的规矩 |
| **详情（点任何一条）**：记录卡、拿不准的一点就确认、原话里对应的那一段荧光标出、改动历史、删除（能撤销）；字段直接改留到以后 | 规范 12「原话追溯」；改法先用说的（「刚才那个是 38 不是 28」），一个表单一个表单地做改的界面放到后面 |
| **左右滑换日子**，日子头右边有「前一天 / 后一天」（看得见的替代）；还没到的日子不能看；在看别的日子时说一句，自动回到今天看它凝结 | 规范 12「左右滑换日子」「每个手势都有看得见的替代」 |
| **真机连这台 Mac 用「配对码」**：网关听局域网时显示 6 位配对码，手机在设置里输一次，换回的令牌存在手机钥匙串、Mac 上的 `gateway/.paired.json`（不进仓库）；装到手机时 `install-device.sh` 把 Mac 的局域网名字写进 App（不是秘密）；这台 Mac 自己来的请求（模拟器）不用配对 | 「密钥不进 App」：App 包里不放任何令牌；输错 5 次换码、配好一台换码，防一个一个试 |
| **一句话总结**：网页版 canvas-summary v3 原样搬来（网关 `/v1/summary`）；记录变了才重新生成（按能说的记录算指纹），连着说好几句等安静 15 秒再生成；待办、待确认的不算 | 照网页版 summary.ts；不白花钱、不说不对的话 |

### M2c 做的时候定的（Claude，2026-10-18）

| 决定 | 理由 |
|---|---|
| **评测照搬网页版的 340 条**（`gateway/evals/parse-cases.json`，网页版提交 eeede65），每条一部「假手机」：已有的记录、前面几句对话都在它的本机数据里，背景包、写回改动包都照手机的规矩；评分照网页版 `evals/run.ts` 的 score | 「和网页版一样准」要用同一把尺子量；全部跑一遍约 0.5 元 |
| **还没搬的能力单独数**：目标、问答、学说法、提醒时刻、没说时间的提醒（M4）、钱的去向和分类、值不值、人情——这些用例里对应的检查不算对也不算错；带着已有目标、个人词典的用例（背景里要有它们才答得对）整条不算 | 搬一样进来一样，分数不虚高也不冤枉 |
| **类别表在手机上，网关新建的类别放进改动包**（契约 v3 的 `newCategories`），手机在同一个事务里先建类别、再写记录 | 网关照旧不存任何东西 |
| **生活领域的颜色**：规范 01「默认给」里有的照用（育儿、家人朋友樱，健康砖，家务陶，出行湖，娱乐藤）；没列的四个定为宠物陶、兴趣麦、购物杏、办事石；AI 照网页版 Skill 写的颜色名（gray、brown……）换成九个领域色 | 同一个领域在所有地方是同一个颜色（规范 01） |
| **背景包里的记录照网页版 contextEntries**：这段话那一天和前后一天的全部记录，加上最近 30 条没做完的待办（不管哪天的）；原来是「那一天 + 前后三天没做完的待办」 | 「昨天下馆子花了 216」再说一遍要认得出是同一件事，「昨天跑的是 8 公里」要改得到昨天那条；网页版评测的用例都是照这个背景写的 |
| **去重照网页版搬全**（`gateway/src/dedupe.ts`）：AI 漏判时程序兜底——同一天、同类、名称相同或互相包含、时间对得上就是同一件；多说了时间、数量就补上那一条；原话说的是约数（「两百多」）按范围比；明说了「又…一次」「第二次」是新的一次，光一个「又」在回顾那天的事时只是「接着」；AI 把今天又做的事写成改以前那条（没说是改、没提那天）照今天新的一次记 | 规格 6.3「不能重复计算」；这些都是网页版训练场找到、改过的 |
| **两种话不问 AI**（`gateway/src/quick.ts`）：上一句问了「要删这几条吗？」、这一句是「对」「删吧」「算了」——程序直接删或不删；同一句话 5 分钟内又发了一遍、上一次记下了东西——直接说刚才已经记过 | 删除不靠猜；以为没发出去又点一次不会记两遍；省一次 AI |
| **接口契约升到 v4**：改动包带上问了要不要删的那几条（`awaitingDelete`），手机记在这段话上（数据库 v4），下一句的对话里带回去 | 「对」删的是问的那几条，不是 AI 再猜一遍 |
| **给你的那句话照网页版 composeStep**：回复里不出现内部编号、不替系统做承诺（「会提醒你」）；回复里问的话变成追问；说了话却什么都没发生要说明白（要改没找到哪条就问、都记过了就说一声）；只是提问照实说问答还没做；很难受时换成程序写的那句。要做的事说的「周五」「大后天」由程序往后数 | 不让人以为没发出去再发一遍；AI 不编造、不许诺 |
| **待办的提醒提前到 M2 做**（产品主人 2026-10-19 在手机上说「5 分钟之后叫我开会」没被提醒）：网关照网页版算提醒时刻（「5 分钟后」从说话时往后数；只说钟点是下一次到这个钟点；说了哪天没说几点是那天早上 7:30；没说什么时候、或者时间已经过了就问一句），待办带上 `remindAt`（可选字段，不升版本）；手机照数据库排系统通知（PourPlatform/Reminders），记录一变就重排，做完、删掉的撤掉，App 开着时也弹出来 | 产品主人要先看到效果；本地通知到点不用连网、不靠服务器。重复的提醒（「每天早上七点」）、提醒的设置页还在 M4 |
| **界面改成 1 比 1 照网页版的生活画布**（产品主人 2026-10-19 看了手机上的 iOS 版和网页版：「UI 先只做生活画布，样式不需要你设计了，1 比 1 做网页的那种」）：顶栏菜单和搜索、日期标题、一句话总结、时间轴和「未定时间」、类别卡片（睡眠横条、进食窗口、待办勾选、心情圆点）、底部输入框向上展开成对话面板（收据后面就是「撤销」）；颜色、字号、间距照网页版 tokens.ts（`PourDesign/Web.swift`），写法照网页版 shared（`WebText`、`WebReceipt`）；类别颜色换回网页版的九种标签色（数据库 v6、网关、预置类别一起换）。「纸·墨·青」和标签栏那一套不再用在画布上 | 产品主人认得、喜欢网页版；先把画布做到一模一样，别的页面以后一个一个照搬 |
| **评测里网页版也还没做好的用例**（`since` 比网页版当时的阶段 6 大）只查意图，和网页版一样 | 同一把尺子 |

### 改方向：复刻网页版（产品主人 2026-10-19）

| 决定 | 理由 |
|---|---|
| **网页版的服务器当后端，iOS 只做原生界面，1 比 1 照网页版**（产品主人选的 B）：网页版服务器原样跑在这台 Mac 上（给手机用的端口 5188，数据在 `~/Developer/pour-phone-data`），以后搬阿里云；手机读写它的接口（`PourKit/PourAPI`），听它的推送刷新；没网时说的话先存在手机上，连上了自动发 | 产品主人：「之前说重新设计和重写那个方向是错误的」。复刻网页版最快的路是直接用它的代码：AI 能力和业务规则从第一天起和网页版一模一样，网页版以后改了手机自动跟上；按今天的速度估计两个账号并行 2–3 天、一个账号 4–5 天追平（[交接说明](../复刻网页版-交接.md)） |
| **手机自己存数据、自己的 AI 网关那一套停用**（`PourData`、`PourAI`、`gateway/` 先留着，复刻完再删） | 网关的整理规则本来就是从网页版搬的，网页版服务器里都有；两套逻辑长期并存会越走越远 |
| **两个账号分工**：账号 1 做地基、画布、对话、详情、设置、没网先存、通知、手感；账号 2 搬页面（关于我、钱、回顾、目标、笔记库、搜索和问答），每页一个分支 | 页面之间不依赖，并行最快；共用的东西（接口层、令牌、导航）先由账号 1 做好 |

## 4. 怎么验收

**我先自验收**（`docs/验收/M2-自验收.md`）：`scripts/check.sh --full` 全过；网关的测试全过；M2a 起每一步在「iPhone 15 · iOS 27」模拟器上走一遍你的验收脚本、截图留证；M2c 的评测和速度数字。

**你验收**（每一步做完都可以先看）：
1. 打 5 句不同的话，看卡片怎么凝结出来
2. 点一张看原话（M2b）
3. 左右滑看昨天（M2b）
4. 说「早上跑了五公里 中午和小王吃面三十二」，看它认出人和钱

## 5. 风险

- 网页版的流水线和它的数据库缠得紧，改成纯函数要一处一处拆；拆的过程中用网页版的评测守住准确率
- 手机要连得上 Mac 上的网关：模拟器直接连；真机要同一个 WiFi，Mac 不能睡着
