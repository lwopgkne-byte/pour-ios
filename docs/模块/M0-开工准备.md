## 1. 这个模块回答什么

## 2. 两个决定带来的变化

| 原方案 | 现在 | 影响 | 以后什么时候要回头 |
|---|---|---|---|
| 用 iOS 27 SDK 构建（Xcode 27） | 用 Xcode 26.6（iOS 26.5 SDK）；最低系统仍是 iOS 26 | iOS 27 才有的新接口暂时不用（Core AI、iOS 27 玻璃的新调节），这些本来也不在 M0–M2 的关键路径上 | 第一次往 App Store Connect 上传前（苹果每年春天会要求新 SDK），或者你的 iPhone 装不上时 |
| Xcode Cloud 自动构建 → TestFlight | **本机一键检查** + 推送前自动跑；GitHub Actions 只在合并进 `main` 前跑一次 iOS 构建和测试 | Xcode Cloud 和 TestFlight 都要付费会员，现在用不了 | 加入开发者计划后，按原方案补上 Xcode Cloud 和 TestFlight |
| 你从 TestFlight 装 | **用数据线从这台 Mac 装到你的 iPhone**（免费的个人签名） | 免费签名装的 App **7 天后会打不开**，要重新装一次（插上线我来装）；一台手机最多 3 个这样的 App | 同上 |
| — | 后面几个模块也会碰到付费会员的门槛 | M2 的「设备证明」（防盗刷 AI）、M10 小组件共享数据、M11 iCloud 同步都要付费会员 | **最晚 M2 联调网关前**，我会提前一个模块提醒你再决定 |

## 3. 做什么

| # | 内容 | 说明 |
|---|---|---|
| 1 | 一键环境脚本 `scripts/bootstrap.sh` | 检查 Xcode 版本、用 Homebrew 装 XcodeGen 和 SwiftLint（版本写在 `Brewfile`）、启用推送前检查、生成工程；可以重复运行 |
| 2 | 工程和分层骨架 | `project.yml`（XcodeGen，不提交生成的工程文件）；本地 Swift 包分出 `PourCore`、`PourData`、`PourAI`、`PourDesign`、`PourPlatform`、`Features/*`，**依赖方向靠编译器守住**（没声明的依赖根本编译不过）；Swift 6 严格并发检查 |
| 3 | 只有启动页的空 App | 纸色底（亮暗两套）+ 安静的「Pour」字标 + 底部小字版本号和构建号（验收时认得出是哪一版）；临时图标（纸底墨字），正式图标在 M1 出三个方案；只做竖屏 |
| 4 | 隐私清单雏形 | `PrivacyInfo.xcprivacy`：不跟踪、不收集；只声明真正用到的系统接口（M0 没有用到） |
| 5 | 一键检查 `scripts/check.sh` | 生成工程 → 编译 → SwiftLint → 单元测试（包在 Mac 上直接跑，App 在模拟器上跑）→ 隐私清单格式 → 仓库里没有密钥文件；推送前钩子在改了 `ios/` 时自动跑它，没过推不上去 |
| 6 | GitHub Actions 的 iOS 任务 | 合并请求进 `main` 时在干净的 macOS 机器上跑一次 #5；先实测每次用多少分钟（私有仓库的 macOS 分钟按 10 倍算），**会不会产生费用开工时先查清楚再告诉你** |
| 7 | 主分支保护 | **等你决定 GitHub Pro**（见第 6 节第 2 条）；不开就靠推送前检查 + 只通过合并请求进 `main` 的规矩 |
| 8 | 20 条技术决定的记录（ADR） | `docs/ADR/`，A1–A20 每条一份：选了什么、没选什么、为什么；A3 按这次的决定写 |
| 9 | 能力对照表 | `docs/能力对照表.md`：网页版每一项能力（SPEC 各章 + 需求文档）在 iOS 上是同 / 升 / 改 / 去、在哪个模块；以后每个模块验收时逐条勾 |
| 10 | 对拍「标准答案」导出脚本 | `scripts/export-golden.ts`：先搭好框架、导出 M2 要用的日期时间函数的一批样例到 `fixtures/golden/`；只新增脚本，**不改网页版的任何规则** |
| 11 | 核对网页版家底 | 提示词第 2 节的数字（代码行数、单元测试 1,095 项、评测用例 340 / 13 / 28 / 48……）实际数一遍；**评测不跑**（要用密钥、要花钱），只数用例 |
| 12 | 文档写回 | 这次的两个决定写回 03（A3、M0、第 12 节）、01 第 10 节、README「在 Mac 上开工」、`CLAUDE.md` 的 Mac 一节（补上命令）、08 变更记录；顺手改 05 第 1 节「开发方案第 5 节」→ 第 9 节 |
| 13 | Node 版本 | 仓库要求 Node 24，这台 Mac 是 25；bootstrap 里装上 24 并切过去，保证网页版的检查和别的电脑结果一样 |

**不做**：设计系统和真正的页面（M1）、网关（M2）、Xcode Cloud 和 TestFlight（等付费会员）。

## 5. 怎么验收

**我先自验收**（写进 `docs/验收/M0-自验收.md`，每条附真实命令和结果）
- `scripts/check.sh` 全部通过；GitHub Actions 的 iOS 任务绿
- 在一个全新的临时目录里重新 `git clone` → 跑 `bootstrap.sh`，计时 ≤ 15 分钟（如实说明：这不是一台全新的 Mac）
- 空 App 在模拟器上：亮色、暗色、最大字号、小屏和大屏各截一张图看过
- 故意写一条违反依赖方向的代码 → 确认编译不过；故意放一个假的密钥文件名 → 确认检查拦住
- 能力对照表、ADR 20 份齐全；网页版家底数字和提示词对得上（对不上的如实列出）

**你再验收（约 10 分钟，要你在 Mac 旁边）**
1. 用数据线把 iPhone 插到 Mac 上，手机上点「信任」，输入锁屏密码
2. 我来装 App；手机上按我给的步骤打开「开发者模式」、信任开发者（第一次才要）
3. 点开 Pour，看到启动页；底部的版本号和我报给你的一致
4. 把手机切到深色模式再看一眼

> 如果你的 iPhone 已经是 iOS 27：当前的 Xcode 26.6 可能装不上去。我会先实测；装不上的话，免费装 Xcode 27 就能解决（到时问你）。
