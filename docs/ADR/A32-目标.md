# A32 3.0 目标：按「我在乎的」分组、一行一个目标；每种目标一句人话；GROW / WOOP / 每周回顾是程序的事实 + 现成的回答；提醒手机自己排

- **状态**：已定（3.0 第 7 步）
- **日期**：2026-11-02

## 决定

- **首页按「我在乎的」分组，一行一个目标**（`GET /api/goals/home` 一次拿全）：环（新状态：在正轨上 · 落后 · 暂停 · 还早）、
  名字、一句人话（06 交互细节 12.2 的表，一字不差：「比应达少 78 公里，聊聊怎么调？」「30 天做到 26 天」）。坚持单独一组，
  右边 14 天的格子。按住出菜单（`contextMenu`）、左滑暂停 / 继续（`swipeActions`），全部带撤销，不弹确认框
- **「我在乎的」存在设置里**（`settings.care`：几块、名字、图标、包含哪些类别、每季度的分、我想成为和点没点头），
  没定过是默认的四块（健康 · 钱 · 成长 · 关系）；目标上一个 `care` 字段，没填按类别自动归
- **每种目标的一句话由程序算**（`goal-state.ts`）：到一个数（应达、实际、差多少、预测带）、坚持每天（30 天做到几天、
  补假按顺序自动用、作废、不攒）、每周几次（连续 8 周算成习惯了）、平均、不超过、往下、做完就算（里程碑）。
  预测带照原型的算法：28 天里前后两个 14 天的速度一快一慢
- **聊聊怎么调（GROW）、花 1 分钟想清楚（WOOP）、每周回顾都是「程序摆事实 + 现成的回答」**：事实（「10 月你跑了 3 次，
  都在周末早上」）和每个办法的新日期是程序算的；AI 只写措辞和从原话里挑现成的回答（带出处），结果缓存在 `goal_ai`，
  没开 AI 时用程序的说法。每周回顾的「一个观察」也是程序找的规律
- **提醒手机自己排**（07 7.6，和待办的提醒同一套）：服务器给单子（`GET /api/goals/reminders`）——「如果就」
  （按时间：每周几天各排一个重复的通知；按地点：到家的时候，要先在手机上定一次「家在哪」，位置只存在手机上）、
  每周回顾（默认周日 20:00，设置里能改、能关）、先停一个月回来的前一天晚上 20:00。待办的提醒让出目标占的那几个，
  合起来不超过系统的 64 个。暂停的、在设置里关了的不排；点通知打开那个目标 / 直接打开每周回顾
- **定目标走理解卡**（`POST /api/goals/understand`）：从哪句话算、已经算进去多少（原话）、拿不准时三个现成回答、
  已经有的不重复建；点「对」才建

## 为什么

- 目标页最常见的问题是「我现在怎么样、差多少」：一句人话比一张表好懂；数是程序算的，不让 AI 编
- 一行一个：系统的左滑只认一整行（两列并排的卡片左滑不了）；第一屏照样放得下 5 个
- 我在乎的只有几块、改得少：存设置里够了，不另开一张表
- 提醒到点要响，不能靠电脑开着：和待办的提醒一样交给手机

## 没选的

- **首页两列卡片**（原型里只有一个的组并排）：系统的 `swipeActions` 只在 List 的一整行上有；自己做左滑要重写手势和读屏
- **care_areas 单独一张表**（01 9.12 写的）：几块、几个字段，放设置的 JSON 里，迁移和撤销都简单；以后要按块统计再拆
- **AI 直接给办法和新日期**：日期算错了没人发现；程序算、AI 只说话
- **服务器推「如果就」**（Server酱、Bark）：要电脑开着、要填推送密钥；手机自己排到点就响

## 后果和什么时候重新看

- 「到家的时候」要先在手机上定一次家（目标页那一行、设置 → 提醒和推送「家在哪」）；没定时不排，那一行写着「还不知道家在哪」
- 每个工作日的提醒占 5 个系统通知；目标多了待办的提醒会少排几条（最近的先排）
