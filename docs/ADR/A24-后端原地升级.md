# A24 后端原地升级，不推倒重写；为安卓、网页准备好接口

- **状态**：已定（产品主人 2026-10-26 选的）
- **日期**：2026-10-26

## 决定

- Pour 服务器（`~/Developer/pour`）不重写，在现在的基础上升级成谁都能接的后端（[产品优化](../模块/产品优化.md) R8）：
  - **接口说明书**：每个接口干什么、怎么调、返回什么、谁能调；测试核对每个接口都写进去了
  - **版本号**：`/api/meta` 带接口版本，App 每次请求说自己的版本；不兼容的改动让旧 App 说「请更新 Pour」
  - **设备登录**：PIN 只用来配对一次，之后每台设备一把自己的钥匙（服务器只存哈希，能在「Pour 设置」里踢掉）；网页以后照样能用现在的 cookie
  - **时区写进设置**：默认北京时间，不跟着电脑走
- 安卓、网页的界面现在不做；多人账号等搬阿里云、给别人用时再做

## 为什么

产品主人在《产品优化建议》里写了「后端架构重新写……不能比网页端功能差……后面要兼容 iOS、安卓、网页」。评审时查了：

- 2.0.0 删网页时只删了界面，后端的功能一个没少；网页的每一页都已经在 App 里（A22、A23）
- 服务器约 2.6 万行代码、1000 多项单元测试，整理评测 99.93%；推倒重写要几周，而且一开始一定比现在差，违反 00 提示词的红线「不能比现在差」
- 它本来就是用 HTTP 和 JSON 说话的后端，哪种客户端都能接；接安卓、网页真正缺的是说明书、正式的登录、上云

## 没选的

- **推倒重写**（换一套架构从头写、功能 1 比 1 再做一遍）：几周时间，测试和评测全部重来，中间会比现在差
- **先不动、等上云时一起做**：小组件和分享扩展现在就要用设备登录；时区现在就错着

## 后果和什么时候重新看

- 服务器的接口只加不改的规矩照旧（CLAUDE.md「接口是合同」），说明书和覆盖测试让它看得见
- 上云、给别人用时重新看：多人账号、正式的身份验证（手机号或 Apple 登录）、「只认本机」的那几样怎么办
