# A21 独立仓库：iOS 搬进 pour-ios，和网页版完全分开

- **状态**：已定
- **日期**：2026-10-18（产品主人：「这个代码要完全在另外一个新的代码仓库，不能和之前的网页有污染；开发任务完成之后整理工程目录，删除没相关的东西」）

## 决定

- 新建私有仓库 `lwopgkne-byte/pour-ios`，只放 iOS 这个产品：App、设计画廊、PourKit、脚本、文档和检查；以后它自己的 AI 网关（A08）也放这里（`gateway/`）——网关是 iOS 的后端，不是网页版。M1 自验收通过后搬。
- **保留 iOS 部分的提交历史**：只取 `ios/`、`docs/ios/`、`fixtures/golden/`、iOS 的 CI；目录搬到仓库根（`ios/` → 根，`docs/ios/` → `docs/`）。
- **和网页版之间没有代码依赖**：
  - 对拍用的标准答案（`fixtures/golden/`）是从网页版规则导出的**冻结数据**，写明出处（仓库和提交号）；导出脚本留在网页版仓库
  - 样张的演示数据（`Gallery/Resources/Sample.json`）同样是冻结数据，写明出处；导出脚本不带过来
  - 文档里提到网页版的地方（SPEC、规则出处），改成指向网页版仓库固定提交的链接
- 网页版仓库删掉 `ios/`、`docs/ios/` 和 iOS 的检查（推送前检查里 iOS 那一段、`ios.yml`），README 写一句「iOS 在 pour-ios」。只有一份 iOS 代码。

## 为什么

产品主人要求。iOS 是独立的产品：检查、发布、依赖都和网页版不同，放在一起互相拖累（推送 iOS 要先跑网页的 npm 检查，CI 靠路径过滤分开）。

## 没选的

- iOS 继续放在网页版仓库的 `ios/` 目录：产品主人不要
- 新仓库从零开始、不带历史：丢掉 M0、M1 每次改动的理由
- 用 git submodule / subtree 引用网页版：还是耦合在一起

## 后果和什么时候重新看

- 以后要更多标准答案（M2 心情说法和时间推断、M7 目标计算……）：在网页版仓库跑一次导出，结果拷进 pour-ios 的 `fixtures/golden/`，写明提交号
- 网页版已经冻结（产品主人：网页版不管了）。网页版的规则以后不会变；就算变了，iOS 也不自动跟——这是有意的
