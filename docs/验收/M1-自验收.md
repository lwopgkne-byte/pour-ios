## 2. 自验收中发现、改了根因的

| 发现 | 怎么发现的 | 根因和改法 |
|---|---|---|
| **钱的月历丢了 1–3 号** | 看截图 | 1 号前的空格和每一天用了同样的编号，SwiftUI 当成同一个——改成不重复的编号 |
| **方块图的列表里「睡眠」出现三次，「娱乐」「冥想」不见了** | 看 AX5 截图 + 走屏器报「有字没露出来」 | 和上一条同一类：方块用领域色当编号，几个类别共用一种颜色（睡眠、娱乐、冥想都是藤）就重了——改成用名字当编号；开发和测试时编号重复直接拦下（`assert`）；追问的选项也去重 |
| 未来的日子旁白读「没记」 | 读代码 | 改成「还没到」 |
| **危险按钮的系统红在白底上约 3.6:1** | 系统审计 | 要读的文字要 ≥ 4.5——亮色改用实测达标的深红，暗色用系统暗色的红；测试实算（规范 01 已改） |
| **图表对比系列的灰在白卡上 2.67:1** | 审计 → 算数 | 必要图形要 ≥ 3——改深一档（3.78）；新增「必要图形 ≥ 3」的测试（原来只测了文字，漏了图形）（规范 01 已改） |
| 月历最深的格子上，日期只有 4.40:1 | 审计 → 算数 | 底色封顶 20% → 12%；测试实算（规范 09 已改） |
| 字调大时按钮上的字被截断 | 审计 | 按钮的字锁成了一行——改成可以换行（和系统按钮一样） |
| 不能点的按钮读不清是什么 | 审计 | 不能点时字用淡墨（约 6.9:1），看得出是什么、只是不能点（规范 08 已改） |
| 加载中的按钮，旁白还读看不见的字 | 审计 | 看不见的字不读，转圈说「正在处理」 |
| **AI 标识卡在句子中间**（第一行末尾） | 看截图 | 标识画成小图嵌进文字，换行时跟着最后一个字走 |
| 多行的字被报截断、行距偏松 | 审计 → 对照 | 我用「字号 × 1.2」估行高，多加了 1–2 点；规范的行高本来就是系统字体自带的——只给原话之声加行距 |
| 方块图第二行四块挤不下，「家人朋友」被截 | 审计 | 按实际宽度算第二行放得下几块，放不下的进「还在攒的」（规范 09 本来就这么写） |
| 字调大时方块图的块不长高 | 审计 → 对照实验 | 块是固定高度——改成最小高度；大字号时方块图变成一行一个领域的列表 |
| 大字号时目标、列表行、时间轴、统计卡、钱的月历、图标说明挤成窄列 | 看截图 | 按规范 11：大字号时「名字 + 数」上下两行、时间列移到上方、两列变一列、月历变列表 |
| 一周七天的星期字长不大 | 审计 | 图是固定高度——柱子区固定，字按自己的大小排 |
| 11 点的「一」「三」「1」「7」太细 | 审计（同色同号只有笔画少的字不过） | 图表刻度从常规改成半粗，看着清楚多了（规范 02 已改）。之后审计对星期的单个字仍时报时不报——实验证明是它量单个字不准（第 4 节），颜色本身由测试实算 7:1 以上 |
| 倾倒栏的占位例子在窄屏、大字号时会被截 | 审计 | 放得下给完整的例子，放不下只说「说点什么」——永远不截断 |
| 「今天」的一句话总结、钱的对比句被报截断 | 审计 → 对照实验 | 不是我们的问题（见第 4 节）；顺带把 AI 标识改对了 |
| **大字号时一组胶囊、一组按钮、对比横条、时间去向、录音栏、收据的一行、钱的记录卡被挤成「一个字一行」** | **看 AX5 截图**（审计查不出） | 根因是同一类：字放在**固定宽度**里（对比横条 64 点、40 点，时间去向 44 点），或者几样东西硬挤在一行。改成：一组东西放不下就换行（新组件 `PourFlowLayout`）；「名字 … 数」在大字号时上下两行（新组件 `PourTitleValueRow`，记录卡、收据、时间轴都用它）；要对齐的列用跟着字号变的宽度。规范 11 写进「放字的地方不用固定宽度、固定偏移」 |
| 「待确认」用固定偏移盖在右上角，字调大时压住标题和数 | 看截图 | 排进版面里：记录卡在右上角单独一行，收据的一行跟在数后面（规范 03、08 已改） |
| 录音时的计时在大字号时折成「0:0 / 3」 | 看截图 | 计时永远一行，提示换到下一行 |
| 一周七天柱子上方的「最多」在大字号时折成「最 / 多」 | 看截图 | 大字号时改到图上方一整行「周日 · 最多」 |
| 样张底栏里的占位例子被截成「…」 | 看截图 | 和倾倒栏用同一个占位组件：放不下就只说「说点什么」 |
| 原话块的荧光只是颜色，旁白读不出标的是哪一段 | 读代码 | 旁白多读一句「标出的是：……」 |
| 用了系统已经不建议用的写法（字用 `+` 拼接） | 编译警告 | 改成一段带样式的字（`Text(_:person:)`），认出的人名照样是青色 |

**我自己的检查方法上的问题（也改了，这一类最危险：检查本身错了，「通过」就不可信）**：
- 一开始审计只看第一屏——系统审计只量屏幕上看得见的部分。改成一屏一屏往下滑着审
- 用「第一段字动没动」判断滚动停没停、到没到底——第一段字常常是导航栏的标题，收起以后就不动了：**结果样张只审了第一屏、画廊每页最多审两屏，还是边滚边审的**（我前面说的「样张 0 问题」只算第一屏，不算数）。改成看滚动区域里所有字的位置；走完再查一遍：**每一段字都必须完整露出来审过一次**，少一段就算没通过
- 系统审计里「截断」「动态字体」两项审完会把页面挪走（实测几十点到一屏多），和对比度一起审时，对比度量的是正在动的页面，报出一堆假问题。改成分开审，每一项之前都把页面拖回这一屏；实验证明这两项也只查看得见的字，所以每一屏都要审（`testAuditOnlyChecksVisibleText`，苹果哪天改了这个测试会失败）
- 样张盖在画廊首页上，首页的导航栏还在界面里、只是点不到——找导航栏找到了它，把可见区算小了。改成只认看得见的导航栏
- 往下翻用的系统「滑一下」滑多远、带多少惯性说不准。改成按住慢慢拖、停住再松手，滚多少就是拖多少，每一屏从还没审过的第一段字开始
- 滚动边缘的渐变区我先估了 80 点，放过得太宽（页面末尾的字永远在里面，等于没审）。改成**从截图像素量**：导航栏下沿往下约 26 点；底部玻璃栏往上的投影亮色约 24 点、暗色约 36 点（第一次只量了屏幕最左边一列，那里没有玻璃栏、量少了，审计在离玻璃 40 点以内还在报——改在玻璃栏正上方量）；各留余量用 40 点、44 点。一段字只有完整地出现在这两段以外才算审过
- 「说不出是哪个元素」的对比度问题原来整类放过；检查方法改对以后一次都没再出现——那条放过删掉了，连同当时用来证明它的逐张审计
- 画廊原来用系统列表展示组件，列表会把不能点的行变淡、行里的字长不大——和正式 App 不一样。改成和正式 App 一样的页面

## 4. 审计里不算数的（每条都有证据）

系统的无障碍审计很有用（上面很多问题是它找出来的），但它自己也有毛病。不算数的只有三类，写在 `GalleryUITests` 里，每条都有证据；每一条放过的都打在日志里，数得清：

1. **系统的滚动边缘和玻璃栏的投影**：内容滚到导航栏下面（和它下面的一段渐变），或者在底部浮动玻璃栏（标签栏、倾倒栏）下面和它往上的一段投影里时，审计量出来的对比度不准——那是滚动边缘，不是要读的内容。大小是**从截图像素量的**：导航栏下沿往下约 26 点；玻璃栏往上的投影亮色约 24 点、暗色约 36 点，审计在离玻璃 40 点以内都量不准——各留余量用 40、44 点。只对**对比度**放宽，截断、可点范围、动态字体照样算；而且走屏器保证**每一段字都在渐变以外完整露出来审过一次**——所以放过的只是「同一段字在边缘时的那一次」，没有哪段字因此没被审
2. **审计自己的毛病，用实验证明过**（`testAuditProbeStillMisreportsWrappedText`、`testAuditStillMismeasuresGlyphsAndHighlights`，哪天苹果修好了，实验会失败，提醒删掉豁免）：
   - 会换行的字一律被报「截断」——系统自带的 Text 放一句中文或英文、换五种写法，全都被报；单行的中文不被报。代价：28 点以上的大字单行被截断时审计查不出——这类标题都很短，靠截图检查
   - 系统最小的文字样式 caption2 本身被报「动态字体只支持一部分」
   - 单个字的小标签量不准：同色同号的「三」报对比度不够、「一」和两个字的「三月」不报；最大字号时 38 点的「三」也报。所以图表的星期（一到日）不算对比度；颜色本身由颜色测试实算（亮色 7.4:1、暗色 9.1:1）
3. **核实过的五处**（按原文放过，别的照样算）：
   - 画廊·颜色「杏」：黑字白底，截图清楚，同一列别的领域名都不报
   - 一行字完整显示却被报「截断」：画廊·颜色「操作 · 按钮、链接、选中」、画廊·组件 倾倒栏输入中的「中午和小王吃面 三十二」、样张·关于我 统计卡的「最常在一起 · 34 天」。系统自带的 Text 放「最常在一起 · 34 天」一样被报（去掉空格、只有中文、只有英文的都不报），写进了实验
   - 画廊·字 带荧光的原话：一模一样的原话块去掉荧光就不报（实验）；荧光上的墨字由颜色测试实算（亮色 15:1 以上、暗色 8.4:1）

## 6. 没做的、已知问题

- **截图对比测试（和基准图比）推到 M2**：视觉还没锁定，现在存基准图每改一次就要全部重来；截图矩阵和审计照常跑
- **旁白（VoiceOver）全程走查没做**：自动审计查了每个元素都有说明；真的用旁白走一遍要在真机上
- **性能没量**：M1 只有静态的样张，没有数据库和计算；M2 起按性能预算量
- **这台 Mac 上的 iOS 27.1 模拟器只支持 iPhone Duo**（一种宽屏的机型），所以 iOS 27 只在它上面测了；iPhone 17 系列只能跑 iOS 26.5
- 网页版演示数据有一条「开会」开始时间落在了第二天（网页版的毛病，产品主人说网页版不修），样张里没放这一条

## 7. 产品主人怎么看（约 15 分钟）

我已经在这台 Mac 的模拟器里打开了「Pour 画廊」（iPhone 17 Pro · iOS 26.5）。用鼠标点、拖，就像手指一样。

1. **样张 5 屏**（最重要）：首页「样张」里点「今天」「收据」「关于我」「钱」「回顾」，每屏从上滑到下；底下的标签栏也能点。看完点右上角的 ✕ 回首页
2. **换暗色再看一遍**：按键盘 ⇧⌘A（或模拟器菜单「Features → Toggle Appearance」），再翻一遍样张
3. **App 图标**：首页点「App 图标」，点一个方案 → 按 ⇧⌘H 回到主屏看图标 → 再点开画廊换下一个。三个都看看
4. （可选）颜色、字、组件、图表这几页是零件清单；「动效和触感」里的触感模拟器上摸不到，要等手机
5. **拍板两件事**：
   - **D10「纸·墨·青」这个方向行不行**——说感觉就行，比如「青太冷」「太素」「暗色太黑」
   - **选一个图标**：① 「倾」字 ② 倾斜的杯子 ③ 一笔青线

你拍板后我锁定令牌 v1、把选中的图标放进正式的 Pour App，然后合并这个模块。
