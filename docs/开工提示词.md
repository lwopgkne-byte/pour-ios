# 开工提示词

> 在一台新 Mac 上第一次打开 Claude 时，把下面「复制这一段」整段发给它。以后在新会话里接着干活，只要说：「读 CLAUDE.md 和 docs/README.md，接着做」。
>
> 2026-10-20 起是第二阶段：App 的每一页都有了（界面照原来的网页版），电脑上只剩 Pour 服务器；接下来专门为 iPhone 打磨体验、AI 能力和交互。

---

## 复制这一段

```
你好。我是 Pour（倾）的产品主人，不是开发者。Pour 是一个 iPhone App：只有一个输入框，我只管倾倒，AI 负责把混沌变成结构。
现在每一页都做出来了，界面照原来的网页版；数据、业务规则和 AI 都在电脑上的 Pour 服务器里。
接下来要把它打磨成专门为 iPhone 做的 App：最好的 iOS 手感、最好用、最美——只有好用，别人才愿意用。
这台 Mac 上你没有以前的记忆，所有要求、决定和规矩都在两个仓库里。

【第一步：准备环境、拉两个仓库】
1. 检查这台 Mac 上有没有：最新的 Xcode（打开过一次、登录了我的 Apple ID）、git、Homebrew、GitHub CLI（gh）、
   fnm 和 Node 24。缺什么就一步一步带我装，每一步告诉我点哪里、输入什么。
2. 仓库是私有的：用 gh auth login 带我在浏览器里登录 GitHub、授权一次。
3. 拉 App：git clone https://github.com/lwopgkne-byte/pour-ios.git ~/Developer/pour-ios ，进去运行 scripts/bootstrap.sh。
4. 拉服务器：git clone https://github.com/lwopgkne-byte/pour.git ~/Developer/pour ，进去 npm install；
   先用演示数据起一个服务器给你看效果（数据放在临时目录，不碰我的数据）。
   我的真实数据和密钥不在仓库里：要搬过来时告诉我怎么从旧电脑导出、在这台用「Pour 设置」导入、填密钥。

【第二步：读懂再动手】
按顺序完整读：
1. pour-ios 的 CLAUDE.md → docs/README.md → docs/00-提示词.md（总要求）→ docs/01-现在的App.md
2. pour 的 CLAUDE.md 和 SPEC.md 的第零章（产品理念）、第一章（设计原则）
3. 两边的 git log，pour-ios 的 docs/验收/，知道做到哪了
读完用大白话给我一份 5 分钟能看完的总结：你理解的目标和标准、现在的样子、第一件要做的事、需要我准备什么。

【第三步：开始做】
按 docs/00-提示词.md 第 9 节的顺序，一块一块来：每块写一页小方案留档（我不看方案，你自己决定），
开分支做，你先自验收（scripts/check.sh --full、截图），再装到我的手机上给我看结果。

【一直要遵守的】
- 最高标准：最好的 iOS 手感、最好用、最美；拿不准时问自己「一线 App 会不会让它出门」
- 我只看结果：你自己决定，做完先自验收，再让我在手机上看
- 汇报用中文大白话：做了什么、为什么、要我做什么、怎么验证
- 拿证据说话：每条「通过」都附实际跑过的命令和结果；没跑过的不能写「通过」
- 不读、不打印、不改任何密钥文件；密钥不进仓库、不进 App；密钥和 PIN 我自己用「Pour 设置」填
- 我的数据（服务器的数据目录）不提交、不改、不删；重启服务器前先备份数据库
- 高风险的事先问我：正式环境的数据和配置、密钥、签名证书、付费、正式发布、不可逆的数据变化
- 出了问题改根因，同类的一起修，补测试；确认过的变更写回文档
- 我说「今天先到这」时：跑检查 → 提交 → 推送
```
