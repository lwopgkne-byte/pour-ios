# 开工提示词

> 在一台新 Mac 上第一次打开 Claude 时，把下面「复制这一段」整段发给它。以后在新会话里接着干活，只要说：「读 CLAUDE.md 和 docs/README.md，接着做」。
>
> 2026-10-18 起 iOS 在独立仓库 `pour-ios`（ADR A21）；M0、M1 已经做完——新 Mac 上用这一段准备环境、读懂方案，然后从 `docs/验收/` 和 git log 看到做到哪了接着做。

---

## 复制这一段

```
你好。我是 Pour（倾）的产品主人，不是开发者。我们要把 Pour 做成一线水准的 iOS App：
做到最好的 iOS 手感、最好用、最美、最好的设计——只有好用，别人才愿意用。
这台 Mac 是新的，你没有以前的记忆。所有需求、决定和规矩都在仓库里。

【第一步：准备环境、拉仓库】
1. 检查这台 Mac 上有没有：最新的 Xcode（打开过一次、登录了我的 Apple ID）、git、Homebrew、GitHub CLI（gh）。
   缺什么就一步一步带我装，每一步告诉我点哪里、输入什么。
2. 仓库是私有的：用 gh auth login 带我在浏览器里登录 GitHub、授权一次。
3. 拉仓库：git clone https://github.com/lwopgkne-byte/pour-ios.git ~/Developer/pour-ios ，然后进入这个目录。

【第二步：读懂再动手】
按顺序完整读：
1. CLAUDE.md
2. docs/README.md → docs/00-提示词.md（总要求）→ 01 到 08 → docs/设计规范/ 的全部 12 份
3. 网页版仓库里 SPEC.md 的第零章（产品理念）和第一章（设计原则）——链接在 docs/README.md
读完用大白话给我一份 5 分钟能看完的总结：你理解的目标和标准、整个路线、第一步要做什么、需要我准备什么。
我确认你理解对了，再往下。

【第三步：M0 开工准备】
按 docs/03-架构与开发方案.md 第 10 节的 M0：
1. 先写 docs/模块/M0-开工准备.md（模块小方案：做什么、怎么验收、需要我做什么），给我确认
2. 我确认后开 feature/ios-m0-setup 分支开始做
3. 需要我亲手操作的（登录 Apple ID、加入苹果开发者计划、在 App Store Connect 里点确认、在 iPhone 上装 TestFlight……），
   一步一步告诉我点哪里
4. 做完你先自验收，写 docs/验收/M0-自验收.md；然后让我在 iPhone 上从 TestFlight 装上验收

【一直要遵守的】
- 最高标准：最好的 iOS 手感、最好用、最美、最好的设计；拿不准时问自己「一线 App 会不会让它出门」
- 一个模块一个模块来：小方案我确认 → 做 → 你先自验收 → 我再验收 → 通过才合并
- 汇报用中文大白话：做了什么、为什么、要我做什么、怎么验证
- 拿证据说话：每条「通过」都附实际跑过的命令和结果；没跑过的不能写「通过」
- 不读、不打印、不改任何密钥文件；密钥不进仓库、不进 App
- 高风险的事先问我：正式环境的数据和配置、密钥、签名证书、付费、正式发布、不可逆的数据变化
- 出了问题改根因，同类的一起修，补测试；确认过的变更写回文档
- 我说「今天先到这」时：跑检查 → 提交 → 推送
```
