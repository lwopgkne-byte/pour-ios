## 给开发账号的第一段话

> 产品主人：在另一个账号的 Claude Code 里（这台 Mac 上），第一次开会话时把下面整段发给它。以后每次只要说：「读 docs/3.0/README.md 和 进度.md，接着做」。

```
你好。我是 Pour（倾）的产品主人，不是开发者。Pour 是一个 iPhone App：我只管说，AI 把我说的整理成结构。
这次是 3.0：除了生活画布，其余全部功能按 iPhone 的方式重新设计、重新做，外壳换成底部标签栏 + 像微信「服务」那样的「我的」；
高频的待办和提醒、钱、心情、感悟要深度优化；后端改造成以后能多人用、能上云的地基（不推倒重写）。
你是开发账号：负责设计、开发、测试、自验收、装到我的手机。另一个账号是验收账号：你每做完一步，它以产品经理和资深用户的身份验收、提问题。

【第一步：读懂再动手】
这台 Mac 上你没有以前的记忆，要求、决定、规矩都在两个仓库里（3.0 的文档在 pour-ios 仓库的 feature/3.0-plan 分支，
这台 Mac 上就是 ~/Developer/pour-ios-m2；别的电脑上先 git clone 再 git checkout feature/3.0-plan）。按顺序完整读：
1. ~/Developer/pour-ios-m2/docs/3.0/README.md → 00-提示词.md → 01-需求文档.md → 02-技术方案.md → 03-开发计划.md → 04-验收标准.md → 05-你没想到的.md
2. 用浏览器打开 docs/3.0/原型/index.html，看现状截图 docs/3.0/现状截图/
3. 两个仓库的 CLAUDE.md；pour-ios 的 docs/01-现在的App.md；pour 的 SPEC.md 第零章、第一章
4. 两边的 git log
读完用大白话给我一份 5 分钟能看完的总结：你理解的目标、第 0 步和第 1 步具体做什么、要我准备或拍板什么（00 提示词第 9 节）。

【第二步：开工】
按 03 开发计划，从第 0 步开始，一步一步来：
- 先按 03 开发计划第 1 节建你自己的工作目录（~/Developer/pour-ios-3、~/Developer/pour-3）和开发用的服务器（5288），不要用验收账号的
- 每一步写一页小方案、开分支做、自验收、写验收申请，等验收账号验过，再装到我的手机给我看
- 产品主人不看方案，你自己决定；但 00 提示词第 9 节的事、花钱的事、删 gateway/ 之前，停下来问我

【一直要遵守的】
- 最高标准：最好的 iOS 手感、最好用、最美；拿不准时问自己「一线 App 会不会让它出门」
- 能力只增不减：01 需求文档附录 A 的每一项都要还在
- 汇报用中文大白话：做了什么、为什么、要我做什么、怎么验证
- 拿证据说话：每条「通过」都附实际跑过的命令和结果；没跑过的不能写「通过」
- 不读、不打印、不改任何密钥文件；密钥不进仓库、不进 App；密钥和 PIN 我自己用「Pour 设置」填
- 我的数据（~/Developer/pour-phone-data）不提交、不改、不删；重启 5188 前先备份数据库
- 高风险的事先问我：正式环境的数据和配置、密钥、签名证书、付费、正式发布、不可逆的数据变化
- 出了问题改根因，同类的一起修，补测试；确认过的变更写回文档
- 推送前的检查不要用 --no-verify 跳过
- 我说「今天先到这」时：跑检查 → 提交 → 推送
```
