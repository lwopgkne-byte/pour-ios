## 2. 分几步（顺序就是优先级）

### 2.1 第 0 步：地基和清理

1. **把最新的合进 main**（产品主人 2026-10-27：「使用当前最新的」）：App 仓库 `feature/demo-all`（含产品优化八步、演示数据、3.0 文档）快进合并进 `main`，打标签 `ios-2.8`；服务器 main 已经是最新（2.8.2）
2. 删掉合并过的功能分支（本地和 GitHub 上的）；`~/Developer/pour-ios-m2` 这个工作目录以后不用（验收账号也不再用它）
3. 删不用的代码：`PourData`（把还在用的 `Reminder` 挪到 `PourPlatform`）、`PourAI`、设计画廊 `Gallery/` 和 `GalleryUITests/`、旧的 `Pour*` 设计系统；`gateway/`——**删之前问产品主人一句**（`.env` 里有他的密钥）
4. 演示服务器搬家：5288 + `~/Developer/pour-dev-data`（第 1 节）
5. 截图工具正式化：`AppUITests/TourShotsUITests.swift`（验收账号写方案时用的，从 `docs/3.0/工具/TourShotsUITests.swift` 拷进去），连演示服务器、每页一屏一屏截；`scripts/tour-shots.sh` 一条命令出全部截图和拼好的长图
6. 验收流程：GitHub 上建标签 `3.0`、`验收`、`bug`、`体验`；`docs/3.0/进度.md`、`docs/3.0/验收/`
7. 写 ADR A26（一套设计系统）
- **验收**：`main` 构建、测试全过；`scripts/check.sh` 通过；仓库里搜不到 `PourAI`、`Gallery`；截图工具一条命令出全部页面

### 2.2 第 1 步：设计系统 3.0 + 新外壳 + 数据层

1. 设计系统：令牌统一到 `Theme`；组件库（需求文档 3.2 的每一个，带全部状态），每个组件一个预览（`#Preview`）和快照式的界面测试
2. 外壳：标签栏「今天 · 待办 · 钱 · 我的」+ 搜索；说一句（标签栏附件）；路由换成有类型的；链接照旧能开；去掉抽屉菜单和每页的黄色横幅
3. 「我的」：头、四个快捷（这一步先接到现有的入口：记一笔先打开对话并填好「/记 」，后面几步换成正式的）、常用（管理）、全部功能格子、最下面三行；服务器 `GET /api/me/hub`
4. 数据层：页面缓存、写操作队列、推送失效（02 技术方案 4.3）
5. 这一步**只换外壳和底子**：各功能页先原样放进新外壳（`Web*` 的页面临时包一层），后面几步一块一块重做
- **验收**：需求文档 2.1–2.6 逐条；冷启动、切标签的时间（真机）；没网时打开每个标签都有内容；所有旧链接能打开（`pour://open?path=` 一个一个试，列表在小方案里）

### 2.3 第 2–10 步：一块一块重做

每一步都一样：
1. **服务器先做**：接口和规则（需求文档每章的「服务器要做的」）→ `npm run check` → 改了 AI 规则跑评测 → 演示数据补上 → `npm run demo:check`
2. **App 再做**：照原型和需求文档；只用设计系统 3.0；把这一块的 `Web*` 页面删掉
3. **自验收**：00 提示词第 11 节的九条；附录 A 这一块的逐条对照表；前后截图并排
4. **验收申请**（3.1）→ 验收账号验 → 改 → 再验 → 过了
5. 装到产品主人的手机（5188 先升级服务器）→ 告诉他看哪里 → 他说可以 → 合并进 main、打标签

## 3. 两个账号怎么交接

### 3.1 验收申请（开发账号写）

每一步做完，在 `docs/3.0/进度.md` 里这一步下面写，并在 GitHub 上开一个合并请求（PR，标签 `验收`）：

```
## 第 N 步 验收申请（日期）
- 分支 / 提交：feature/3.0-xxx @ abc1234（App）、feature/3.0-xxx @ def5678（服务器）
- 怎么跑起来：服务器 5288（演示数据）怎么起；App 用哪个模拟器、什么启动参数
- 做了什么（大白话，5 条以内）
- 红线的数字（00 提示词第 5 节，每条附命令和结果）
- 附录 A 对照表（这一块的每一项：还在 / 在哪 / 合并到哪）
- 前后截图（`scripts/tour-shots.sh` 出的，放 docs/3.0/验收/第N步/）
- 已知问题、没做的、偏离原型的地方和理由
```

### 3.2 验收（验收账号做）

1. 拉提交，在自己的工作目录和 5299 上跑起来（不用开发账号的环境）
2. **以产品经理 + 资深真实用户的身份用**：按需求文档这一章的「什么时候用」一个场景一个场景走；每个操作看手感（回应、触感、动效）、看所有状态（空、加载、出错、没网、数据少、最大字号）
3. 对照：需求文档的验收标准、附录 A、原型方向、设计系统（有没有硬编码、有没有第二套样子）
4. 每个问题一条 GitHub Issue（标签 `3.0` + `bug` / `体验` / `缺功能`）：在哪、怎么做出来、看到什么、应该是什么、截图；**严重程度**：挡发布 / 要改 / 建议
5. 写 `docs/3.0/验收/第N步.md`：结论（通过 / 改完再验）、问题列表、截图
6. 挡发布的都关掉以后，验收账号在 PR 上写「验收通过」，开发账号再装到产品主人的手机

### 3.3 产品主人

- 只看结果：开发账号装到手机后，用大白话告诉他「这一步多了什么、去哪看、怎么试」
- 他说的问题，开发账号记成 Issue（标签 `产品主人`），优先改

## 4. 风险

| 风险 | 怎么办 |
|---|---|
| 外壳一换，链接、推送、小组件打开的页面对不上 | 第 1 步列出全部链接逐个测（界面测试） |
| 重做一页时悄悄少了功能 | 附录 A 对照表是验收申请的必填项；验收账号逐条核 |
| 缓存显示了过期的东西（比如勾了的待办又出现） | 写操作先改缓存；推送来了让缓存过期；测试「勾了 → 杀掉 App → 没网打开」 |
| 快加认错时间 | 程序认时间，60 个以上的说法写单元测试；打字时就显示认出的时间，错了当场能改 |
| 新的原话格式（「午饭 25」「心情挺好」）让整理变差 | 先写评测用例；全量评测不低于 99.9% 才合并 |
| 演示数据跟不上 | 每一步的验收里有「演示数据有这一步的新东西」 |
| 免费签名 7 天过期（11 月 2 日） | 到期前重装；建议产品主人加入开发者计划（05 你没想到的第 4 条） |
| 两个账号同时改东西 | 第 1 节的分工；验收账号不写代码 |
