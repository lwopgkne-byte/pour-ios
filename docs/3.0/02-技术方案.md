## 1. 现在的底子（2026-10-27 盘点，开工前核对）

**服务器**（`~/Developer/pour`，2.8.1）
- Node 24 + TypeScript；Fastify 5；better-sqlite3（SQLite，33 张表，带迁移版本号）；zod 校验；fflate（导出）
- AI：DeepSeek（函数调用、关掉深度思考、Skill 前缀走缓存）；16 份 Skill；整理评测 340 多条 99.93%；审核员考卷；训练场
- 本地向量模型 bge-small-zh（`@huggingface/transformers`，约 24MB，CPU）：按意思搜索、相关笔记、主题的起落
- 约 2.8 万行业务代码 + 1.25 万行测试（1150 多项）；约 125 个接口，接口说明书有覆盖测试，`/api/meta` 带接口版本
- 登录：PIN 配对一次 + 每台设备一把钥匙（服务器存哈希，能踢掉）；「只认本机」的管理操作走「Pour 设置」
- 一个进程里跑：整理队列、早上回顾和晚上提醒、预警、周报月报、夜里体检、每小时备份；推送 `/api/events`（SSE，全局一条）、Bark / Server酱
- 部署：这台 Mac 上 `nohup node --import tsx server/src/index.ts`；5188 给手机（数据在 `~/Developer/pour-phone-data`），5199 演示数据

**App**（`~/Developer/pour-ios-m2`，`feature/demo-all`，构建 88）
- SwiftUI，最低 iOS 27；包 `PourKit`：`PourAPI`（接口类型和客户端、`Show` 写法）、`PourDesign`、`PourCore`、`PourPlatform`（通知、钥匙串、健康、日历、语音），还有不用了的 `PourData`、`PourAI`
- 约 2.2 万行；**三套样子并存**：生活画布 2.0 的 `Theme`、其余页面从网页搬来的 `Web*`、第一阶段的 `Pour*`（只剩设计画廊在用）
- 导航：一个页面 + 左上角抽屉菜单 + 字符串地址（`pagePath`）；详情是自己画的半屏层（`WebPeek`）
- 数据：每次打开现拿，**不缓存**；只有「说一句」有发件箱；待办提醒**只排看到过的那几天**
- 系统能力：小组件（4 个 + 控制中心）、分享、Siri、健康、日历、App 里的语音识别——都接了
- 测试：PourKit 单元测试；每页一个界面测试（连假服务器 `StubServer`）+ 无障碍审计
- 签名：免费签名，7 天重装；App + 2 个扩展用满「3 个 App」

## 2. 后端要不要重写：评估

产品主人问：「后台是否要全方面的重写，因为后面要适配 iOS、安卓、网页……一次性把基础的架构全部弄好」。

### 2.1 三条路

| | A. 推倒重写 | **B. 原地改造平台层（推荐）** | C. 用现成的云后端（BaaS） |
|---|---|---|---|
| 做法 | 换一套技术（比如 Go / Java + PostgreSQL），功能 1 比 1 再写一遍 | 业务层不动，改账号、存储、任务、推送、部署这一层 | Firebase、Supabase、LeanCloud 这类 |
| 时间 | 2–3 个月，中间一直比现在差 | 2–3 周（不含备案这些手续） | 业务逻辑一样要写；迁移 1–2 个月 |
| 风险 | 高：钱、心情、关于我的算法细节多，1150 项测试和评测都要重来 | 低：每一步都能跑、测试兜底 | Firebase 国内用不了；别的在国内的合规、私有化都受限 |
| 能力 | 先变弱，再慢慢追回来 | **只增不减** | 受平台限制 |
| 结论 | 违反红线「能力只能比现在强」 | **选它** | 不适合 |

### 2.2 为什么 Node + TypeScript 够商用

- Pour 的重活是**等大模型**（几秒一次），不是算东西：服务器大部分时间在等网络，Node 最擅长这个
- 一台 4 核 8G 的云服务器，几千个天天用的人没问题；再多就按人分到几台（3.2）
- 网页版可以直接复用服务器的 TypeScript 代码（类型、写法函数，比如 `fmtNum`），三端说法天然一致
- 现有的 Skill、评测、训练场、演示数据都是 TypeScript 写的，留着就是资产

### 2.3 「专门的商用后台」是哪三样

1. **Pour 服务**（App 连的）：就是现在的服务器，改造成多人、能上云（第 3 章）
2. **运营后台**（运营的人用的网页）：看用户、用量、反馈、处理注销——**看不到原话**（第 7 章）
3. **基础设施**：云服务器、数据库、备份、推送、日志、监控、告警（第 5 章）

## 3. 后端改造：平台层

### 3.1 两种运行方式，一套代码

- **本机模式**（现在的样子）：一台电脑、一个人、PIN 配对、`secrets.json`、「Pour 设置」。开发、演示、产品主人在上云前自己用，都用它
- **多人模式**：账号登录、每人一个数据库、控制库、按人调度。阿里云上用它；在这台 Mac 上也能完整跑起来（开发和测试）
- 一个配置项切换（`POUR_MODE=local|multi`）；业务代码不分两份

### 3.2 存储：每人一个 SQLite + 一个控制库（ADR A27）

**为什么不是一个大 PostgreSQL**：现在的业务代码全是同步的 better-sqlite3 调用（28k 行，几百处 SQL），换成 PostgreSQL 要把几乎每个函数改成异步、每条 SQL 改方言——这就是重写。

**每人一个数据库**：
- 每个账号一个 SQLite 文件（`users/<分片>/<用户号>/pour.db`），结构就是现在的 `pour.db`；**现在的 `pour.db` 原样就是第一个用户的库**
- 请求进来：验证令牌 → 打开这个人的库（打开过的放在缓存里，久不用的关掉）→ 业务代码照旧用 `db`
- 好处：业务代码几乎不改；**每个人的数据天然隔开**（隐私上能说清楚：「你的数据是一个独立的文件」）；导出、备份、注销都按文件做；迁移脚本照旧（打开时检查版本，懒迁移）
- 代价：跨人的统计不能直接查（运营后台看的是控制库里的汇总）；同一个人的请求要落到同一台机器（3.10）
- 向量还在每个人自己的库里（现在就是）

**控制库**（账号、设备和令牌、订阅、用量、调度、反馈、运营操作记录）：
- 云上用 RDS PostgreSQL（多台机器共用、有主备）；本机开发用 SQLite 同一套表（通过一层很薄的存取接口隔开）
- 只放「谁、多少、什么时候」，**不放原话**

### 3.3 账号和登录

| | 本机模式 | 多人模式 |
|---|---|---|
| 注册 / 登录 | PIN 配对（现在的） | 手机号 + 短信验证码（国内主流）；**用 Apple 登录**（iOS 上一点就登，不用输手机号）；微信登录以后（要开放平台和公司） |
| 令牌 | 设备钥匙（现在的） | 访问令牌（15 分钟）+ 刷新令牌（每台设备一个，服务器存哈希，能踢掉）——就是设备钥匙的升级版 |
| 多台设备 | 「Pour 设置 → 设备」 | App「我的 → 设备与安全」：看、改名、踢掉 |
| 注销 | — | App 里申请 → 7 天冷静期 → 删用户库、备份、控制库记录，发一封确认 |

- 开发阶段还没有短信服务和域名：多人模式先用**邀请码 + 口令**登录（只给自己和测试用），短信、Apple 登录的接口先留好，上云时接上
- 「只认本机」的管理操作（填密钥、导入、评测、审核员考试）：多人模式下变成运营后台里管理员才能做的事；用户自己能做的（导出、注销、改设置）进 App

### 3.4 接口

- **路径不变**（App、链接、说明书都不用动）；所有业务接口在「当前用户的库」上执行：Fastify 的钩子验证令牌、打开这个人的库挂在请求上，路由从请求上拿库（现在是闭包里的 `db`）——这是改造里改动最多、但最机械的一处，靠现有测试兜底
- **每个请求只能碰自己的库**：加一组测试专门证明 A 的令牌拿不到 B 的任何东西
- **接口契约（OpenAPI）**：从 zod 生成（zod 4 自带 JSON Schema 转换），放进仓库；检查程序核对「说明书、OpenAPI、App 的类型」三者一致。以后安卓、网页按 OpenAPI 生成客户端
- **版本**：沿用 `/api/meta` 的接口版本和 `X-Pour-Api` 请求头（2.7.0 已有）
- **推送**：`/api/events` 改成按人：只把这个人的变化推给这个人的设备

**3.0 新加的接口**（详见 01 需求文档各章的「服务器要做的」）：
- 待办：`GET /api/todos`（今天、接下来、没定时间、已完成，带提醒的全部未完成）；推迟（改提醒时间）；重复规则；完成时间
- 心情：心情这一页一次拿全（今天的几刻、这个月的格子、几张洞察卡）
- 感悟：感悟这一页（按标签、按时间、收藏、重温）
- 我的：一次拿全「我的」页的数字（记了几天、几段话、认识几个人、每个格子上要不要写数）
- 反馈：带截图和日志的反馈

### 3.5 后台任务按人调度

现在一个进程里的这些，都改成「按人」：

| 任务 | 现在 | 3.0 |
|---|---|---|
| 整理原话 | 一个队列 | 每人一个队列，全局限并发（大模型的速率） |
| 早上回顾、晚上提醒、预警 | 一个定时器，按本机时间 | 调度表记每个人下一次什么时候跑，按他的时区和设置 |
| 周报月报 | 一个人 | 每人一份，错过的补生成 |
| 夜里体检 | 一个人 | 每人一份，排在夜里错峰跑 |
| 备份 | 每天一个 zip | 云上：实时备份每个库（3.8）；本机：照旧 |
| 主题起名、发现 | 一个人 | 每人按需 |

- 调度表在控制库：`(用户, 任务, 下次时间, 状态)`；worker 取到期的、打开那个人的库执行
- 一台机器时 worker 就在同一个进程里；多台时单独起 worker 进程

### 3.6 AI 用量和成本

- 每次调用记到人（现在 `ai_runs` 已经有用量，按人汇总进控制库）
- 每人每月上限（免费、订阅不同）；超了：原话照存，整理排到下个周期，或者换便宜的模型——**原话永远不丢**
- 全局熔断：大模型出错率高、或者花费异常时自动降级并告警
- 运营后台看每人、每天、每种任务的花费

### 3.7 推送

- **待办提醒以手机本地通知为主**（不联网也会响），服务器推送兜底（手机很久没打开 App 时）
- iOS：APNs（**要加入苹果开发者计划**）；密钥放云上的密钥管理，不进仓库
- 安卓（以后）：厂商通道（华为、小米、OPPO、vivo、荣耀）走聚合服务
- Bark / Server酱：本机模式留着（产品主人在用）

### 3.8 文件和备份

- 导出 zip、以后的图片和语音：对象存储 OSS（私有，临时链接）
- 用户库：Litestream 这类工具把每次写入实时备份到 OSS，再加每日快照；**每个月做一次恢复演练**
- 本机模式照旧：每天一个 zip、保留 30 份

### 3.9 配置、密钥、日志、监控

- 密钥：本机模式 `secrets.json`（照旧，不读不打印）；云上用阿里云的密钥管理，环境变量注入
- 日志：结构化、**不含原话和金额**（只有编号、耗时、错误）→ 阿里云日志服务
- 监控和告警：请求量、错误率、接口耗时、大模型耗时和花费、任务积压 → 超了发钉钉 / 短信
- 错误追踪：服务器和 App 都接（Sentry 自建或阿里云的；国内用不了 Firebase）

### 3.10 以后人多了怎么扩

- 第一年一台机器（垂直加配置）足够；控制库里每个用户有「分片」字段，入口按分片把请求转到对应的机器；用户库跟着分片走
- 搬一个人到别的分片 = 复制他的库文件 + 改分片字段

### 3.11 安全

- 全站 HTTPS，证书自动续；限流和防刷（验证码接口尤其要）；输入全部 zod 校验（已有）
- 每个请求只能碰自己的库（测试证明，3.4）；管理员也看不到原话；运营操作全部留痕
- 云盘加密、备份加密；令牌只存哈希；密码类的东西永远不进日志
- 隐私政策、敏感个人信息单独同意（健康、心情、钱）——文案见 05 你没想到的第 2、3 条

## 4. App 的技术方案

### 4.1 外壳（ADR A25）

```swift
NavigationStack(path: $path) {
    CanvasView()                                          // 首页 = 生活画布，没有标签栏
        .toolbar {
            ToolbarItem(placement: .topBarLeading) { MeButton() }          // 「我」→ 我的（全部功能）
            ToolbarItem(placement: .principal) { DayButton() }             // 今天 · 10月27日 ▾ → 日历
            ToolbarItem(placement: .topBarTrailing) { SearchButton() }     // 搜索，和现在一样
        }
        .navigationDestination(for: Route.self) { RouteView(route: $0) }
}
.safeAreaInset(edge: .bottom) { SayBar() }                // 每一页底部只有「说一句」，往下翻收起
// 主屏幕快捷操作：Info.plist 的 UIApplicationShortcutItems（说一句、记一笔、加待办、记心情）
```

- **路由**：字符串 `pagePath` 换成有类型的路由（`enum Route: Hashable`），一个导航栈（根是画布）；服务器和对话里的链接（`/review/2026-10-18`、`/money/watch`……）照旧认，换成「从画布推哪几页」——`pour://open?path=` 不变
- **详情**：自己画的 `WebPeek` 换成系统的底部弹层（`.sheet` + `presentationDetents([.medium, .large])`），或推入导航栈（内容多的）
- **从格子打开**：`navigationTransition(.zoom(sourceID:in:))`，从「我的」的格子放大进页面
- **生活画布**：内容不动，去掉左上角菜单按钮；它自己的输入框并进全局的「说一句」

### 4.2 设计系统 3.0

- **只留一套**：以生活画布 2.0 的 `Theme` 为准（暖灰底 `#F3F2EF`、白卡片、`#1B56B3` 蓝、宋体原话、圆体数字）；`Web*` 的页面全部换过来，然后删掉 `Web.swift`、`WebControls.swift`、`WebParts.swift`；`Pour*` 和设计画廊一起删
- **令牌**：颜色、字号、间距、圆角、阴影、动效（几种弹簧）、触感——都在 `Theme` 里；每个颜色一个值（只有亮色），但写法保证以后加深色只改令牌
- **组件**（先进组件库，带全部状态，再进页面）：
  - 列表：分组列表行（图标、标题、副标题、右边的值、箭头）、可勾的行、钱的行、原话的行
  - 卡片：分组卡、指标块（大数 + 说明 + 和上次比）、图表卡、发现卡（四个反馈按钮）
  - 「我的」：功能格子（SF Symbol + 一组一色的圆角方块 + 名字 + 角上的数或小圆点），组名在卡片上方
  - 输入：说一句条、快记的数字键盘、心情五档、筛选胶囊、日期和时间（系统控件）
  - 反馈：空状态、骨架、出错、没网条、轻提示（带撤销）
  - 交互：滑动操作、长按菜单（带预览）、下拉刷新、搜索
- **图表**：全部用 Swift Charts，一套主题（颜色、字号、网格、提示），能拖着看数；现在自己画的几种（月历圆点、心情像素、星图）留着，换成同一套令牌
- **SwiftLint 规则**：禁止 `Web.`、禁止硬编码颜色字号间距圆角（已有，扩展到新令牌）

### 4.3 数据层：先出缓存，写操作排队（ADR A28）

- **页面缓存**：每个页面接口的最后一次回复存在手机上（按账号分开，`Application Support/cache/`）；打开一页先显示缓存（顶上不出转圈），同时去拿新的，拿到了无动画替换；没网时一直用缓存，顶上一条细细的「没连上，显示的是 10:32 的」
- **写操作队列**：现在只有「说一句」有发件箱；3.0 扩展成所有写操作：勾待办、改一行、标记已报销……先改界面，再排队发；失败了退回并说一句（带重试）
- **推送失效**：`/api/events` 来了「哪样变了」，让对应缓存过期，正在看的那页重新拿
- **性能预算**（真机 iPhone 15，测了写进验收申请）：冷启动到能点 < 1 秒（有缓存）；推入一页 < 100 毫秒（有缓存）；列表滚动不掉帧；内存 < 200MB

### 4.4 待办提醒（详见 01 需求文档第 4 章）

- 新接口拿**全部未完成、带提醒的**待办，手机排最近的 60 条（系统最多 64 条）；每次打开、收到推送、后台刷新（`BGAppRefreshTask`）都同步一次
- 通知带按钮：「完成」「10 分钟后」「1 小时后」「明天早上」——在后台通过 App Intent 发到服务器（没网就排队）；点通知打开那条待办
- 定了时间的提醒用「时间敏感」级别（专注模式下也能出现，用户可以在系统设置里关）
- 有了 APNs 以后：服务器在提醒时间检查，手机那边没确认排上的，推送兜底

### 4.5 小组件和系统入口（在现有 4 个小组件、控制中心、分享、Siri 的基础上）

- 心情：小组件上直接点五档里的一个（交互小组件）
- 记一笔：点了打开「快记」的数字键盘
- 待办：小组件上勾（已有，接新接口）
- 我的语录：一句话（已有）
- Siri 和快捷指令：「记一笔」「记心情」「今天还有什么待办」
- 免费签名只能有 3 个 App：现在的 2 个扩展已经用满；加小组件不加扩展（同一个扩展里多几种小组件）

### 4.6 测试

- 单元：PourKit（接口解码、写法、路由解析、缓存、写操作队列）
- 界面：假服务器 `StubServer` 加新接口；每个新页面一个测试类，跑无障碍审计
- **截图对照**：把 3.0 方案时用的「全部页面截图」测试正式化（`TourShotsUITests`，连 5199 演示服务器，每页一屏一屏截），每一步自验收用它出前后对比
- 真机：录屏 + Instruments（启动、滚动、内存）
