# 05 测试方案

> 依据：[00-提示词](00-提示词.md) 第 4、6 节。本文回答「怎么证明不比现在差、每个模块怎么验收、出了问题怎么管」。

---

## 1. 质量目标（数字）

| 方面 | 目标 |
|---|---|
| 规则对拍 | 和网页版 **0 处意外不同**（有意不同逐条写理由） |
| AI 评测 | 整理 ≥ 99.9%、每个维度不降；问答 100%；手机口语用例 ≥ 99% |
| 自动测试 | 每次合并全部通过；不允许跳过、不允许「先关掉这个测试」 |
| 性能 | 开发方案第 5 节的预算全部达标（iPhone 13 基准机） |
| 无障碍 | 自动审计 0 问题；每个模块一次旁白全程走查 |
| 稳定 | 内测崩溃率 < 0.2%；卡顿（hang）率进 Xcode Organizer 的「良好」区间 |
| 设计 | 设计审查清单 100% 通过 |

## 2. 网页版有什么，iOS 版对应什么（「不比现在差」的账）

| 网页版 | 数量 | iOS 版 | 目标数量 |
|---|---|---|---|
| 规则的单元测试（`shared`） | 约 400 | PourCore 的单元测试（逐个移植）+ **对拍**（每个函数一批标准答案） | 移植 100% + 对拍覆盖全部要搬的函数 |
| 服务端单元测试（`server`） | 约 380 | 网关测试（AI 流水线的测试原样留在 TypeScript）+ PourData 测试（领域模型、约束、改动包和撤销、同步） | 网关原样保留；数据层新增 ≥ 150 |
| 评测程序自身的测试（`evals`） | 约 180 | 原样保留（评测程序不搬） | 不变 |
| 页面测试（电脑 + iPhone） | 47 个场景、107 次运行 | 界面测试（XCUITest）：每个网页版场景都映射到手机上的流程，再加手机特有的（语音、离线、通知、小组件、分享） | ≥ 60 个场景 × 两种屏幕宽度 |
| 演示数据检查 | 74 项 | `pour-cli demo-check`：74 项全部移植，再加「一整年」数据的检查 | ≥ 80 项 |
| AI 评测 | 340 + 13 + 28 + 问答 48 | 全部沿用，加手机口语约 60 条 | ≥ 490 条 |
| 截图测试 | 无 | 组件和页面 × 亮暗 × 两种字号 × 两种宽度 | 每个组件、每个页面 |
| 性能测试 | 无（靠手动看） | 启动、滚动、计算、搜索、内存的自动测试 | 每个预算一项 |
| 无障碍测试 | 对比度单元测试 | 对比度测试 + 自动无障碍审计 + 可点范围测量 | 每个页面 |

## 3. 测试体系

| 层 | 工具 | 测什么 | 什么时候跑 |
|---|---|---|---|
| 单元 | Swift Testing | PourCore、PourData、PourAI、界面模型的逻辑 | 每次提交 |
| 对拍 | Swift Testing + `fixtures/golden/` | Swift 规则 = 网页版规则 | 每次提交 |
| 数据 | Swift Testing + 临时数据库 | 结构迁移、读写、约束（基础类别不许有上级……）、改动包的应用和撤销、版本历史、导出再导入 | 每次提交 |
| 同步 | 两台模拟器 + CloudKit 开发环境 | 20 个场景：同时改、离线改、删了又改、改了又删、时区不同…… | 每晚 + M13 |
| AI 评测 | 网关评测程序；`pour-cli` 跑问答 | 准确率 | 改 AI 相关时、部署前、每周 |
| 截图 | swift-snapshot-testing（ADR 记录） | 组件和页面长得对 | 每次合并 |
| 界面流程 | XCUITest | 用户从头到尾做一件事 | 每次合并（核心流程）、每晚（全部） |
| 无障碍 | XCUITest 的无障碍审计 + 可点范围测量 | 对比度、标签、动态字体、可点范围 | 每晚 |
| 性能 | XCTest 性能指标 + 系统日志标记 | 启动、滚动掉帧、计算耗时、内存 | 每晚（基准机型模拟器）+ 每个模块真机量一次 |
| 演示数据检查 | `pour-cli demo-check` | 埋的规律找得对、各页面有内容、数字对得上 | 每次合并（1 个日期）、每晚（40 个日期） |
| 弱网和离线 | 网络模拟（高延迟、丢包、断网） | 不丢话、自动重试、状态看得见 | 每晚 |
| 网关 | Vitest + 压测工具 | 接口、额度、App Attest、日志不含原话、100 并发 | 每次提交 + 部署前 |
| 安全 | 自动检查 + 清单 | 数据保护级别、钥匙串、传输安全、日志里没有原话和密钥 | 每次合并 + M15 |
| 内测指标 | MetricKit + Xcode Organizer | 崩溃、卡顿、启动时间、耗电 | 内测和上线后每天看 |

## 4. 对拍怎么做（最关键的一道）

1. 网页版的 `scripts/export-golden.ts` 把每个要搬的函数在一批输入上的结果存成 JSON：`{ 函数, 输入, 输出 }`
2. 输入三个来源：演示数据在 40 个不同的「今天」；网页版单元测试里的输入；随机生成的边界输入
3. Swift 读 JSON、调用同名函数、比较：字符串一字不差；数字按 AI 方案 8.3 的规则（四舍五入、浮点误差 ≤ 1e-9）
4. 报告：多少函数、多少样例、几处不同、每处不同的原因
5. 网页版的规则以后再改 → 重新导出 → Swift 跟着改，两边永远一致

## 5. 测试用的数据

| 数据 | 用途 |
|---|---|
| 演示数据：9 周的那个人（埋 5 真 5 假） | 绝大多数页面、发现引擎、截图 |
| 演示数据：一整年（新） | 「你的一年」、长期趋势、性能 |
| 合成的 3 年数据（约 1.1 万段话） | 性能和极端情况 |
| 第 1 天、第 5 天的新用户 | 空状态、「还在攒」 |
| 评测用例里的背景 | AI 评测 |

**永远不用任何人的真实数据做测试。**（网页版的数据不迁移，iOS 版从零开始。）

## 6. 门槛：什么情况下不能合并、不能发布

| 时机 | 必须全过 |
|---|---|
| 每次提交（本地 + CI） | 编译、SwiftLint（含令牌检查）、单元、对拍、数据、文案禁用词 |
| 每次合并到 main | 上面全部 + 截图 + 核心界面流程 + 演示数据检查（1 个日期） |
| 每晚 | 全部界面流程 + 无障碍 + 性能 + 弱网 + 同步 + 演示数据检查（40 个日期） |
| 改了 AI（Skill、流水线、模型、问答工具） | 相应评测全量通过并出报告 |
| 模块验收前 | 以上全部 + 真机走一遍验收脚本 + 设计审查清单 |
| 发布前 | 以上全部 + 全量评测 + 发布清单（07 第 7 节） |

## 7. 两道验收

### 7.1 第一道：Claude 自验收

自验收报告模板（`docs/ios/验收/Mx-自验收.md`）：

```
# Mx 名字 · 自验收报告
## 一句话结论：可以交给产品主人验收 / 还不行（原因）
## 做了什么（对照模块小方案，逐条）
## 证明
- 自动检查：单元 N 项、对拍 N 个函数 M 份样例 0 处意外不同、界面 N 个流程、截图 N 张……全部通过
- 评测（如果动了 AI）：整理 99.9x%（基线 99.93%），各维度……
- 性能（iPhone 13 真机）：冷启动 xxx 毫秒、滚动掉帧 x 毫秒/秒……
- 设计审查清单：N/N 通过（附不通过后修好的记录）
- 能力对照表：本模块 N 条全部勾上 / 有理由的改动 N 条（列出）
## 截图（亮暗、最大字号、小屏大屏）
## 已知问题和下一步
```

**自验收的标准**：Claude 自己按验收脚本在真机上走一遍，觉得一线 App 也会让它出门，才交出去。

### 7.2 第二道：产品主人验收

验收脚本模板（10–20 分钟，大白话，每一步带截图）：

```
# Mx 名字 · 验收脚本
准备：TestFlight 更新到 x.y.z（构建号 N）；需要网络 / 不需要
1. 打开 App，点下面的「今天」……
   你应该看到：……（截图）
2. 按住输入栏右边的话筒，说「中午吃了碗牛肉面 28」，松开
   你应该看到：……
……
最后：觉得哪里不对、哪里不舒服，直接说，越具体越好（截图更好）
```

验收结果三种：**通过**；**通过，但有几处小问题**（记进下个模块）；**不通过**（列清单，Claude 改根因后重走第一道）。

## 8. 缺陷管理

- 记在 GitHub Issues：标签分模块和严重程度（致命 / 严重 / 一般 / 建议）
- 每个缺陷：**先写能复现的测试（或评测用例）**，再找根因，再修，测试留下来防回归
- 同一类问题一起修（「改根因，不打补丁」）
- 致命和严重的当天处理；内测期间每周过一遍全部未关闭的

## 9. 上线后持续看

| 看什么 | 从哪看 | 不对劲时 |
|---|---|---|
| 崩溃、卡顿、启动时间 | Xcode Organizer、MetricKit | 致命的当天修，分阶段发布可以暂停 |
| AI 准确率 | 每周评测、线上「你改过的地方」的比例（只统计次数） | 掉了就查最近的 Skill 和模型变化 |
| AI 成本 | 网关报表 | 超预算报警，查缓存命中率 |
| 留存和付费 | App Store Connect 的数据（不在 App 里加跟踪） | 每月看一次 |
