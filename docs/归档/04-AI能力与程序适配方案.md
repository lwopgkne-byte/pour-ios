# 04 AI 能力与程序适配方案

> 依据：[00-提示词](00-提示词-v1.2.md) 第 4、9 节；[01 总体方案](01-总体方案.md) 3.1 节 T3、T6；架构见 [03](03-架构与开发方案.md) 第 5、7 节。
> 两件事：**AI 能力**（在哪跑、用什么模型、准确率怎么保住、成本怎么控、合规）和**程序适配**（网页版的 TypeScript 规则怎么搬到 Swift 还一模一样）。

## 1. 现状：网页版里 AI 做的事

| 能力 | Skill | 程序把关（网页版的做法，全部继承） |
|---|---|---|
| 意图识别（记录 / 提问 / 纠正 / 命令） | `router` | 提问时提前开始回答，省一次等待 |
| 整理一段话 | `parse-note` | 时间推断、单条超 24 小时先问、钱要原话里说了、值不值的原话一字不差、类别按同义词归位、去重、「Pour 认识的你」只用来认人认地方不许往上加 |
| 目标 | `goal` | 做不到的目标值、绑定类别和关键词由程序判断 |
| 钱的细节 | （整理流水线的钱步骤） | 报销、借出、退款、人情由程序核对 |
| 纠正分类（通用的错 / 个人的说法） | `classify-correction` | — |
| 问答 | `answer` + 工具 | 数字由工具查、程序核对；答案引用的原话作为来源 |
| 一句话总结 | `canvas-summary` | 记录没变不重写 |
| 每日回顾、周报、月报、早上、晚上、预警 | `daily-review` 等 6 份 | 数字由程序算，句子里的数字逐个核对；禁用责备的说法（`_voice`） |
| 夜里自动检查 | `audit-day` | 一天最多标 5 处 |
| 主题起名 | `name-themes` | 名字太长、带标点、带评价和责备的不要 |

**沉淀下来的规矩**（iOS 版原样继承，写进每个 Skill 和每段程序）
- 能用程序确定的事不交给 AI；AI 只措辞，数字由程序核对
- 原话是源头；没说的不编；说不准就问（一次一个问题）
- Skill 里「# 背景（每次调用时填入）」之前是固定规则、之后才是变量——**命中缓存的输入价格约是没命中的五十分之一**，这条规矩直接决定成本
- 改了 Skill 就跑评测；修 bug 先写能复现的评测用例

## 2. 目标

| 指标 | 网页版现在 | iOS 版要求 |
|---|---|---|
| 整理评测（340 条，多维度） | 99.93% | **≥ 99.9%，每个维度不降** |
| 问答评测（48 条） | 100% | **100%** |
| 纠正分类（13 条）、审核员（28 条） | 现有成绩 | 不降 |
| 手机特有用例（新增） | — | 语音口语、没标点、同音错字、分享进来的长文字：≥ 99% |

## 3. 架构：三种调用

| | 整理 | 单技能 | 问答 |
|---|---|---|---|
| 是什么 | 一段话 → 结构 | 写回顾、报告、总结、起名、夜里检查 | 问你自己的数据 |
| 谁编排 | **网关**（TypeScript，沿用网页版流水线） | **网关**（渲染 Skill、校验输出） | **手机**（工具在手机上查本机数据） |
| 手机发什么 | 原话 + 背景包（见 3.2） | Skill 名 + 程序算好的数字和背景 | 对话 + 工具结果 |
| 网关回什么 | 改动包（建哪些记录、改哪些、问什么） | 校验过的结果 | 模型的回复（流式），网关负责加上系统提示词、计量 |
| 为什么这样分 | 整理是网页版花最多心血的部分，原样沿用最稳；提示词和把关改了不用等苹果审核；多步调用在服务器上跑，比手机来回快 | 同左 | 问答要查你的全部记录：在手机上查，发给模型的只有查出来的那几条（和网页版一样），全部数据从不离开手机 |

### 3.1 网关不记得你说过什么
- 原话、背景、结果只在处理这一次请求的内存里；**日志里没有原话**（自动检查：日志字段白名单）
- 只记：谁（匿名编号）、哪个 Skill、多少 token、多久、成功没有、错误码
- 失败重试用「同一段话的 UUID」做幂等：同一段话不会被整理两次、扣两次额度

### 3.2 整理改成「给背景、回改动」（M2 的主要工作）

网页版的整理流水线直接读写数据库；改成纯函数后，网关和评测、网页版都调用同一份代码：

**手机发的背景包**（典型 ≤ 8 KB）
- 这段原话、说话的本地时刻和时区、日界线
- 今天和昨天的记录（精简格式，睡眠要看前一晚）
- 类别（含同义词）、个人词典、进行中的目标
- 「Pour 认识的你」（人、常做的事、常去的地方，就是网页版的 `describeAboutMe`）
- 最近几轮对话（「接着上一句说」用）、等你回答的追问

**网关回的改动包**
- 要新建、修改、删除的记录（每条带来源：原话里的哪一段）
- 要新建的类别、学到的说法、目标的变化
- 收据的文字、追问、提示
- 全部由程序把关过（网页版的 guards 原样运行）

手机收到后**一个事务**写进数据库，失败就整段回滚、保留「待整理」。

**怎么保证重构不掉准确率**：重构前后同一天各跑一次全量评测，逐条对比；不一致的逐条查清才能合并。

### 3.3 问答在手机上跑
- 工具（网页版 `tools.ts` 里的查记录、查钱、查心情从哪来、查发现……）移植到 Swift，查本机数据库
- 系统提示词（`answer` Skill）在网关上渲染加上去——提示词还是只有一份、改了立即生效
- 数字核对、来源引用（网页版 `answer-text`）在手机上做
- 流式返回：第一个字中位数 ≤ 1.5 秒

## 4. 模型

| 任务 | 默认 | 备用 | 说明 |
|---|---|---|---|
| 意图、整理、目标、纠正分类、问答、回顾、总结、起名 | DeepSeek V4 Flash | 通义千问（已备案） | 网页版评测 99.93% 就是 Flash；关闭深度思考 |
| 夜里自动检查（审核员） | DeepSeek V4 Pro | 通义千问 | 要更强的模型看出整理错了 |

- **模型名由网关管**：手机不知道具体模型，网关配置里改；DeepSeek 2026-07-24 已经停用旧名字 `deepseek-chat`，这种变化只改网关
- **备用切换**：连续出错或超时自动切到备用，恢复后切回；**换模型前必须用评测证明不掉准确率**
- 温度、最大 token、重试一次（输出不合格带着原因重试，沿用 `call-skill`）、超时，全部写在网关配置里
- 价格（2026 年 7 月第三方汇总，以官方页面为准）：V4 Flash 每百万 token 输入 $0.14、命中缓存 $0.0028、输出 $0.28

## 5. 成本控制

| 手段 | 怎么做 |
|---|---|
| 缓存 | 守住「固定在前、变量在后」；每个 Skill 的缓存命中率进每周报表，低于 85% 报警 |
| 封顶 | 网关按用户、按天、按月设上限（具体档位以后随定价定，机制从第一天就有）；到了就排队到第二天并告诉用户，不偷偷降级 |
| 少调用 | 能用程序做的不调用；记录没变的总结不重写；回顾里的句子一天一次 |
| 看得见 | 每天：总成本、每个活跃用户成本、每个 Skill 成本、命中率；超预算报警 |
| 防盗刷 | App Attest + 令牌 + 每个设备的频率限制；异常用量自动冻结并报警 |
| 容量 | 按 10 万日活、每人每天 6 段算：每天约 60 万次整理，平均每秒约 7 次、晚高峰约 50 次；每次整理 2–3 次模型调用 → 高峰约每秒 150 次模型调用。网关无状态、横向扩；**和 DeepSeek 签企业额度**，备用模型分流；M2 压测证明单实例能力，上线前按这个数做一次全链路压测 |

## 6. 评测：全部沿用，再加手机的

| 评测 | 怎么跑 | 什么时候 |
|---|---|---|
| 整理 340 条、纠正分类 13 条、审核员 28 条 | 评测程序从用例生成背景包 → 调用纯函数流水线（本地）或测试环境网关 | 改 Skill / 流水线 / 模型时必跑；部署前跑一次（对测试网关） |
| 问答 48 条 | `pour-cli`（Mac 命令行）按用例建本机数据库 → 跑手机端的问答循环 → 把答案交给网页版的判分程序（判分只有一份，不移植） | 改问答、工具、`answer` Skill 时 |
| **新增：手机口语** | 约 60 条：语音转写的口语（没标点、「嗯那个」、同音错字「跑了五公里→跑了无公里」）、手机上的短句、从别的 App 分享进来的长文字 | M3 起 |
| 训练场（模拟 20 种人带毛病的话） | 继续在服务器上每周跑，找最弱的人群和说法 | 每周 |
| 门槛 | 整体 ≥ 99.9%；每个维度不低于基线；问答 100%；不达标不能合并、不能部署 | — |

**线上变准（用户同意才做）**：用户改了一条记录时，问一次「愿不愿意把这个例子（去掉人名和个人信息）发给 Pour，帮它变准？」——同意了，去标识的例子进候选池，Claude 审过、产品主人确认后才进评测集。不同意的一个字都不发。

## 8. 程序适配：TypeScript → Swift，一模一样

### 8.1 哪些搬、哪些留

| 搬到 Swift（PourCore，手机上算） | 留在 TypeScript（网关） |
|---|---|
| 日期时间、时间推断、格式化 | 整理流水线（router、parse-note、目标、钱的步骤、把关） |
| 类别、同义词、去重、整理格式、收据 | Skill 渲染、输出校验、重试 |
| 目标进度、各种目标类型 | 审核员、训练场 |
| 钱、人情、留意、值不值、钱和日子 | 文案禁用词检查（网关和 CI 都用） |
| 心情、情绪、心情从哪来 | |
| 回顾、周期、报告的数字、提醒的时间表 | |
| 关于我、发现引擎（五道关）、关于我 2.0 全部 | |
| 问答的工具、答案的数字核对 | |

约 8,600 行 TypeScript（`shared/src`，不含测试）+ 问答工具。

### 8.2 对拍：用网页版当「标准答案」

1. 网页版里写 `scripts/export-golden.ts`：对每个要搬的函数，喂一批输入，把「输入 + 输出」存成 JSON（`fixtures/golden/`）
2. 输入从三处来：**演示数据在 40 个不同的「今天」**（覆盖关于我、钱、回顾的全部页面）、**网页版单元测试里的输入**、**随机生成的边界输入**（日期、金额、时间说法）
3. Swift 测试读这些 JSON，逐个比较：字符串一字不差、数字按规则比（见 8.3）
4. 网页版规则改了 → 重新导出 → Swift 测试红了 → 跟着改；**规则只有一处是真相**

### 8.3 两种语言的暗坑（逐条有对策和测试）

| 坑 | JavaScript | Swift | 对策 |
|---|---|---|---|
| 四舍五入 | `Math.round(-2.5) = -2`（向正无穷） | `(-2.5).rounded() = -3`（远离零） | 写一个 `jsRound`，全部用它 |
| 字符串长度、截取 | `.length`、`slice` 按 UTF-16 码元 | `.count` 按字形（一个 emoji 算 1） | 截取和计数一律按 `utf16`，和网页版一致 |
| 排序 | `sort` 是稳定的 | 不保证稳定 | 用稳定排序（相等时按原顺序） |
| 正则 | `\s`、`\p{P}` 的范围 | 不完全一样 | 每个正则单独写对拍用例 |
| 日期 | `Date` 用电脑的时区 | `Calendar` 要显式给时区 | 全部显式传时区；日界线测试 |
| 浮点 | 双精度 | 双精度 | 统计函数（超几何、名次和、BH 校正）在极端值上对拍，误差 ≤ 1e-9 |
| 常量 | 写在各个文件里 | — | 由 TypeScript 生成 Swift 常量文件，不手抄 |

### 8.4 顺序

按依赖由底往上：日期时间 → 类别 → 时间推断 → 目标 → 钱 → 心情 → 回顾 → 关于我 → 发现引擎 → 关于我 2.0。**每个模块用到哪块就搬哪块**（M2 搬日期时间、类别、时间推断、整理格式；M4 搬回顾；M5 搬关于我和发现引擎；M6 搬钱；M7 搬目标……），搬完当场对拍全绿。

| **生成式 AI 登记**（调用已备案模型的应用，属地网信办登记） | Claude 准备材料：服务说明、和模型方的协议、安全自评估、内容安全措施、个人信息保护措施、投诉渠道、应急预案；产品主人提交 | 决定上中国区后马上办（要 2–4 个月） |

| **未成年人** | 年龄分级按实际内容填；是否需要未成年人模式在登记时确认 | 上架前 |

## 10. 隐私设计

| 数据 | 存在哪 | 发给谁 | 存多久 |
|---|---|---|---|
| 原话、记录、版本、纠正、关于我 | 手机 + 你的 iCloud | 整理时：这段原话和背景包发给网关和模型（处理完即忘）；问答时：问题和查出来的那几条 | 你删就没了 |
| 录音 | 不保存（端侧转文字后丢弃） | 不发 | — |
| 向量 | 手机 | 不发 | 跟着原话 |
| 设备的匿名编号（设备证明给的） | 网关数据库 | — | 「删除所有数据」即删 |
| 用量（token、次数） | 网关数据库 | — | 按规定期限 |
| 处理日志（不含原话） | 网关 | — | 按规定期限 |
| 你同意分享的纠正例子（去标识） | 评测候选池 | — | 你可以随时撤回 |

- 心情、健康相关的信息按**敏感个人信息**处理：第一次用到时单独说明、单独同意
- 「隐私中心」里用大白话列出上面这张表，并显示「最近 7 天发给 AI 的段数」
- **说法要和事实一致**：「不保存」只说我们自己的服务器；模型服务商是否保留、保留多久、是否用于训练，上线前查清它的条款、签了数据处理协议后才在隐私说明里照实写；**做不到「不用于训练」的服务商不用**；不说「端到端加密」
