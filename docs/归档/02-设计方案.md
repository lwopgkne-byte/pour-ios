# 02 设计方案：设计宪法 · 设计系统 · 设计审查

> 依据：[00-提示词](00-提示词-v1.2.md) 第 8 节。三层结构：**第一层 宪法**（为什么、什么不能做）→ **第二层 系统**（用什么做，完整规范在 [设计规范/](设计规范/README.md)）→ **第三层 审查**（怎么证明做到了）。
> 宪法和规范的原则对 iOS 和安卓都成立；实现以 iOS 为主，安卓对应见[规范 11](设计规范/11-深色无障碍与适配.md#4-安卓的对应以后做安卓时用)。
> v1.1（2026-10-17）：按产品主人的意见，「素」是全方位的——高亮、字体、颜色、UI 样式……——第二层补全成完整规范；视觉方向 D10 待产品主人看。

## 0. 先诊断：网页版为什么「素」

| 方面 | 现象 | 根因 | 这次怎么改（规范在哪） |
|---|---|---|---|
| 颜色 | 一打开没有记忆点；颜色没有意思 | 唯一的蓝只用在链接和按钮上；颜色不表达含义 | 颜色只表示意思：墨是骨架和操作、**青只表示「它懂你」**、荧光只表示「在这里」、彩色只给数据（[01](设计规范/01-颜色.md)） |
| 高亮 | 重要的和不重要的一样平 | 没有强调层级，没有统一的高亮语言 | 五级强调、八种高亮、每屏上限（[03](设计规范/03-高亮与强调.md)） |
| 字体 | 没有层次和张力 | 字号阶梯窄（13–28）；原话和数字用同一种字 | 三种声音（结构、原话、数字）；字号从 11 到 56（[02](设计规范/02-字体与排版.md)） |
| 样式 | 平、像后台 | 卡片全是浅灰底加细线；一层表面 | 纸 + 卡两层表面、连续圆角、玻璃浮层；每个组件有完整规格和状态（[06](设计规范/06-形状层级与材质.md)、[08](设计规范/08-组件.md)） |
| 图标 | 杂 | 类别用 emoji | 统一 SF Symbols，大小粗细跟着字走（[04](设计规范/04-图标与图形.md)） |
| 生命力 | 没反应、像静态网页 | 几乎没有动效和触感 | 每个操作都有回应；招牌动效「倾倒 → 凝结」（[07](设计规范/07-动效与触感.md)） |
| 图表 | 好用但不好看 | 只是功能，没讲故事 | 一句结论在上、图是证据；每种图都有规格（[09](设计规范/09-数据可视化.md)） |
| 手机感 | 像网页 | 布局从网页搬过来 | 原生导航、拇指区、常驻输入、手势（[05](设计规范/05-布局与间距.md)、[12](设计规范/12-交互模式与页面.md)） |

**一句话**：网页版的克制是对的，错在克制得没有个性、没有体系。这次是**克制，但有灵魂；简约，但每一处都有规范**。

# 第一层 设计宪法

十二条，每条写清来源、在 Pour 里的意思、**怎么检验**。功能和宪法冲突时，砍功能，不破宪法。

### 第一条 先懂人，再画界面
- 来源：唐纳德·诺曼（以用户为中心）、NN/g「贴近真实世界」
- 意思：每个页面先写清**它回答用户的哪个问题**（「今天」回答「我今天过得怎么样」）；用用户的话，不用系统的话（说「整理」不说「解析」）
- 检验：每个页面的小方案第一行是它回答的问题；文案符合[规范 10 的统一叫法](设计规范/10-文案与格式.md)

### 第二条 少，但更好
- 来源：拉姆斯第 10 条、Hick 定律
- 意思：一屏一个主角；一个页面最多一个主要操作；顶层导航不超过 5 个；能合并的不并列
- 检验：数每个页面的主要操作（≤ 1）、标签栏项目（≤ 5）、菜单项（≤ 7）

### 第三条 一个输入框取代所有表单
- 来源：拉姆斯第 1 条（创新只在一处）、Pour 产品理念
- 意思：记录只有一个入口——说一句话。任何地方都不出现「请选择分类」「请填写金额」；需要补的信息由 AI 追问，一次一个
- 检验：全 App 没有用于录入记录的表单

### 第四条 状态永远看得见
- 来源：NN/g「系统状态可见」、诺曼「反馈」
- 意思：任何操作 **100 毫秒内**有回应（视觉或触感）；保存、整理中、待确认、失败、离线，各有安静而明确的样子；等 AI 时看得见进度
- 检验：每个组件的状态清单齐全；性能测试量「按下到回应」

### 第五条 诚实
- 来源：拉姆斯第 6 条、Pour「AI 不编数字」
- 意思：AI 推测的标「推测」；没把握的标「待确认」；数据不够就说不够；只说「同时出现」不说「因为」；**AI 生成的内容有标识**；以后的付费页不用假倒计时、不藏取消
- 检验：审查清单的「诚实」一组；文案禁用词检查

### 第六条 不打扰
- 来源：拉姆斯第 5 条、HIG
- 意思：没有红点、未读数、连续打卡焦虑；通知每类每天最多一次、有免打扰；不弹窗打断输入；权限用到时才问
- 检验：全 App 没有角标和红点；通知规则测试

### 第七条 平台原生，但有自己的声音
- 来源：HIG、Fluent 2（一致性）、拉姆斯第 7 条（持久）
- 意思：系统给的（导航、标签栏、面板、手势、字体、材质）就用系统的，**不自造**；Pour 的个性只放在内容上——颜色的含义、三种声音的字、图表、动效、文案
- 关于 Liquid Glass：网页版的原则说「不追流行视觉（毛玻璃）」。在 iOS 上它是**系统材质**，不是流行装饰。所以**系统浮动控件用它，内容区一律是实的**，不自己做模糊和渐变
- 检验：自定义控件最少，每个都有理由；内容区没有模糊和渐变

### 第八条 结构一眼看清
- 来源：格式塔（接近、相似、连续、共同区域、图形与背景）
- 意思：用**间距**分组，不用线；同类的东西长得一样；一组里只有一种对齐；重要的东西在「图形」上，不在「背景」里
- 检验：分割线只在列表里用；间距只用令牌

### 第九条 好拿、好点
- 来源：Fitts 定律、HIG 点击区域
- 意思：最常用的操作在**拇指区**；点击区域至少 44×44；危险操作远离常用操作
- 检验：界面测试量每个可点元素的实际可点范围

### 第十条 选择少，决定快
- 来源：Hick 定律、NN/g「识别优于回忆」
- 意思：默认值替用户想好；一次只问一个问题；选项 ≤ 7；常用的在前
- 检验：追问一次一个；菜单项计数

### 第十一条 人人能用
- 来源：WCAG 2.2 AA、HIG 无障碍
- 意思：要读的文字对比度 ≥ 4.5:1，大字和必要图形 ≥ 3:1；动态字体到 AX5 不截断；旁白每个元素都有说明；减少动态效果时只淡入淡出；**信息不只靠颜色**
- 检验：自动无障碍审计 + 每个模块一次旁白走查

### 第十二条 细节就是产品
- 来源：拉姆斯第 8 条、原子设计（一致性）
- 意思：每个组件处理全部状态；中文排版、数字等宽、时间说人话；同一件事在所有地方长一样
- 检验：设计画廊的全状态截图；格式由 `PourCore` 统一产出

### Pour 自己的三条（来自产品理念，凌驾于上面所有条之上）
- **原话是源头**：每一个数字、每一条发现都能点回原话
- **AI 只措辞**：数字和结论由程序算，AI 写的句子由程序核对
- **懂你要看得见**：它认识你的每一条（人、地方、说法），你都看得到、改得了——在界面上，这就是「青」

# 第二层 设计系统

## B1 视觉方向（D10，待产品主人看）

**「纸 · 墨 · 青」**

- **纸**：温暖的米白底，像一本好的笔记本
- **墨**：近黑、有温度的字，**以及一切操作**（按钮、链接、选中都是墨色）
- **青**：取自「青瓷」「青山绿水」——水的颜色，和「倾」的意象一致。**只表示一件事：它懂你**（认出你说的人、新发现、收据凝结、「Pour 认识的」）
- **荧光**：荧光笔的黄，只表示「就在这里」（搜索命中、原话追溯）
- **彩色只给数据**：九个领域色、心情五档

**一句话：黑白是骨架，青是懂你，荧光是追溯，颜色只给数据。**

> 从 Manus 学的：单色的克制最显高级——靠层级和留白，不靠颜色。
> Pour 自己的：唯一的品牌色只说一件事，所以青色每出现一次都有意义。

M1 在真机上出样张（今天、收据、关于我、钱、回顾五屏，亮暗各一），产品主人拍板后锁定令牌。若方向要调，只改原始色板，规范的结构不变。

# 第三层 设计审查

## C1 流程（每个模块都走）

1. **交互小方案**：回答什么问题、页面结构草图、组件状态清单、文案 → 产品主人确认
2. **实现**：只用令牌和规范里的组件；新组件先进设计画廊
3. **自动检查**：截图矩阵、无障碍审计、令牌检查、可点范围、对比度、文案禁用词（C3）
4. **Claude 审查**：按 C2 清单逐条打勾，不过的改到过；截图进自验收报告
5. **产品主人真机看**：TestFlight，按验收脚本

## C2 审查清单（逐条判定：过 / 不过）

**宪法**
- [ ] 页面第一行写清它回答的问题；一屏一个主角；主要操作 ≤ 1
- [ ] 没有录入记录的表单；追问一次一个
- [ ] 所有操作 100 毫秒内有回应；加载、空、出错、离线、待确认都设计了
- [ ] AI 推测、待确认、AI 生成的内容都有标识；没有因果说法；数据不够就说不够
- [ ] 没有红点、角标、未读数；没有打断输入的弹窗；权限用到时才问
- [ ] 系统控件用系统的；内容区没有模糊、渐变、阴影
- [ ] 用间距分组；同类元素长一样；一组一种对齐
- [ ] 常用操作在拇指区；可点范围 ≥ 44×44；危险操作远离常用操作
- [ ] 删除和改动可撤销；不可恢复的才二次确认

**颜色和高亮**
- [ ] 只用令牌（自动检查）
- [ ] 彩色只出现在数据里；青只出现在「懂你」清单的场景、一屏 ≤ 3 处
- [ ] 操作（按钮、链接、选中）都是墨色
- [ ] 荧光一屏只有一种用途
- [ ] 一句里加粗 ≤ 2 处；没有叠加的强调
- [ ] 没有红色表示「坏」；危险操作才用系统红

**字体和排版**
- [ ] 原话之声只给原话和叙事、一屏 ≤ 2 处、中文 ≥ 17 点
- [ ] 数字等宽对齐；程序拼的句子中西文之间有空格；原话原样
- [ ] 格式（日期、时间、金额、时长）全部来自 `PourCore` 的格式化函数

**样式和组件**
- [ ] 组件尺寸、圆角、层级符合规范；同心圆角
- [ ] 每个组件全部状态都在设计画廊里截图过
- [ ] 亮色、暗色都看过；iOS 27「更透明 / 更有色调」两种玻璃设置下都可读

**动效和触感**
- [ ] 每个动效说得出表达的因果；时长不超标；可打断
- [ ] 减少动态效果时只有淡入淡出
- [ ] 触感符合对照表；一次操作最多一次
- [ ] 每个手势有看得见的替代
- [ ] 键盘和中文输入法：不挡内容、标记文字时不触发任何自动操作

**无障碍**
- [ ] 要读的文字 ≥ 4.5:1、必要图形 ≥ 3:1（自动检查）
- [ ] 动态字体从最小到 AX5：不截断、不重叠、能滚动（截图）
- [ ] 旁白全程走一遍：名字、顺序、图表能读、播报
- [ ] 信息不只靠颜色
- [ ] 增强对比度、减少透明度、粗体文本三个设置下都正常

**文案**
- [ ] 统一叫法；中文大白话；没有禁用词（自动检查）、没有感叹号

**适配**
- [ ] 375 点和 440 点宽都截图看过

## C3 自动化（让审查不靠记性）

| 检查 | 怎么做 | 什么时候跑 |
|---|---|---|
| 令牌 | SwiftLint 自定义规则：功能代码里不许出现硬编码的颜色、字号、间距、圆角、动画时长 | 每次提交 |
| 对比度 | 单元测试：遍历文字令牌和它们可能落在的背景（亮、暗、增强对比度） | 每次提交 |
| 截图矩阵 | 组件和页面 × {亮, 暗} × {默认字号, AX5} × {375, 440} 宽，和基准图比较 | 每次合并 |
| 无障碍审计 | 界面测试里对每个页面跑系统的无障碍审计 | 每晚 |
| 可点范围 | 界面测试遍历可点元素，量实际可点范围 ≥ 44×44（含扩大可点范围的透明区） | 每晚 |
| 文案 | 禁用词检查（规范 10 第 4 节） | 每次提交 |
| 青的用量 | 截图测试里统计青色出现的区域，超出「懂你」清单的页面报警 | 每次合并 |

## C4 设计画廊（Gallery App）

一个单独的小 App（不上架），展示设计规范的全部：颜色（亮暗、增强对比度）、字体阶梯、间距、每个组件的每个状态、动效、触感（点一下就感觉到）。它是 M1 的验收物，也是以后每个新组件「先上画廊、再进页面」的地方。
